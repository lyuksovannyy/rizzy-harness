# T27

## Threat

An agent runs with more power than the one named: a sub-agent-only agent made a chat's agent (by `agent_id`, `@mention`, `set_agent`, a default or a routine), a removed agent id resolving to a stronger workspace default, an alias shadowing another agent, or a read-only agent writing

## Mitigation

`available_as` is enforced on the master in `Resolver::top_level` for every path that picks a chat's or a turn's agent (typed `SubagentOnly`, 400), and every such path resolves in the chat's own workspace set (the server's agents with that workspace's on top, T79: an id that exists only in another workspace is unknown there); rosters keep only sub-agents, and a sub-agent's spec carries no delegates (depth one).
A stale id fails closed: the chat's prompt is refused with `AgentGone` (409, naming the id; the chat stays readable and `set_agent` makes it usable), a default setting naming a missing or sub-agent-only agent with `BadDefault` (409, naming the setting), an unknown explicit id with `UnknownAgent` (400); routines naming one are blocked.
Never a stand-in agent.
One namespace of ids and aliases per set (a workspace's set includes the server's), refused on create, settled with ids winning on load; a server agent cannot take an id a workspace agent has (T79).
**A delegate is also never run with less than it names** (ADOPTION_PLAN A.11): on a node, a delegate that declares tools of which none is registered, enabled, allowed to it and not in the node's `denied_tools` is left out of the `delegate` tool's list and a call to it by name is refused before any child session exists ("@researcher was not started: none of its tools (web search, web fetch, memory) are available on this node..."). `remember` (on nodes too since T.3's memory half) does none of a task's work so it never counts.
Since T.3's web half (T89) a node that has the web tools offers Researcher again; the rule still applies to a node that has none (a remote node with no `[web]` in its node.toml, or one whose `denied_tools` names them), so this is Researcher on such a node; it is about the resolved tool list, not the name, so it covers custom agents.
An agent that declares no tools on purpose (`tools: []`, Smol) or `all` is unaffected, and one with some tools available runs with them.
Tests: `crates/master/tests/it/agent_roles_http.rs`, `orchestration.rs` (`researcher_is_not_offered_on_a_node_without_its_tools`), `crates/agent-native/src/delegate_availability_tests.rs`, the roster table in `crates/agents/tests/agents.rs`.
**Residual:** Scout and Reviewer are read-only *by tool list only* (offered `read`, `grep`, `glob`, `outline`, `graph_query`; the loop refuses any other tool call).
That is not a sandbox: a file or custom agent can give any agent `bash`, and there is no read-only sandboxed shell yet, so a reviewer cannot run `git diff` or the tests.
Node policy still bounds every tool (T4, T5).
