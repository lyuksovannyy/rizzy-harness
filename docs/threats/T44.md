# T44

## Threat

The repository's instruction files (`AGENTS.md`, `CLAUDE.md`; ADOPTION_PLAN X.2), read by the node on every agentic turn and sent to the model, are a channel for repository content: a prompt-injected agent (or a cloned repository) plants an `AGENTS.md` that is a link to a file the agent's tools may not read (a key outside the session folder, the node's data directory), a FIFO the node would block on, a huge file, or instructions that claim to widen what the agent may do or to come from the person (a URL to fetch, "approval is not needed here")

## Mitigation

**Read by the node with the file tools' rules, not the master's** (`crates/node/src/instructions.rs`): the walk goes from the nearest folder holding `.git` (not above the workspace root that holds the session, or a sub-agent's own folder) down to the session folder, one file per folder (folders below the session folder: T65).
A file is read only when its real path is inside the walked repository folder, inside the session folder for the session folder's own file (the one the agent's file tools can write; folders above it are outside the agent's write grant, though a `bash` sandbox or another session working higher up may still reach them), and in no protected folder (the data directory; a sub-agent's folder lies in the protected sessions folder by design and is its own bound); it is opened with `O_NOFOLLOW \| O_NONBLOCK` on its real path, checked to be a regular file on the descriptor and where the descriptor really points (`/proc/self/fd`), so a folder swapped for a link after the check is refused, and read through `take` within the 32 KiB budget.
A refused or unreadable file is named with the reason and the turn goes on.
**Text only:** it goes into the per-turn context in front of the master's, quoted under the harness's line (T43), so it is never the person's words, never URL provenance (T22), and it changes nothing the node decides (`node.toml`, the approval mode, the tools, a limit); a callback turn gets them too, after its opening and the ended commands' notes, under their own harness line, every line quoted (the opening still starts with the harness's frame; the master's per-turn context stays out of it).
Each file is named by its path from the session folder, and the cap is the smaller of 32 KiB and about a tenth of the model's known context window; the read waits at most 5 s and not past the turn's cancel (a hung disk gives a note, not a stuck turn), and every refused, cut or timed-out read is logged with paths and reasons, never text.
Tests: `node/src/instructions.rs` (order, `CLAUDE.md` only where no `AGENTS.md`, the cap and its note, links out of the repository, the session folder and the granted folder, a FIFO, a protected folder), `node/tests/repo_instructions.rs` (the request the provider gets; an edit seen the next turn; a sub-agent gets them; a URL only in `AGENTS.md` is not fetched; a chat session gets none), the reader's tests for a `.git` file, blank and non-UTF-8 files, a small window's cap, a writing sub-agent's own folder and the timeout and cancel, `agent-native/src/callback_tests.rs` (`a_callback_turn_gets_the_instruction_files_after_its_opening`), `agent-native/src/attachment_tests.rs` (`instruction_files_lead_the_context_block`), `cli/tests/callbacks.rs` (`a_callback_turn_gets_the_repositorys_instruction_files`, through the sandboxed node).
**Residual:** the instructions are meant to be followed, so a hostile repository steers the model as any file it reads could, inside the approval mode and the sandbox; an ancestor folder's link may point anywhere in the repository, including a file outside the session folder the agent's file tools would refuse (usually the person wrote that link, but nothing proves it); a file's hidden characters reach the model as in T43; the files are re-read every turn (a few `stat`s and up to 32 KiB of reads) and sent again only when they changed since the last summary (X.1, T52); a timed-out read leaves its blocking thread running until the disk answers.
