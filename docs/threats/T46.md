# T46

## Threat

Skills (ADOPTION_PLAN X.2; since X.34 step B, the owner's decision of 2026-11-17, the catalogue also takes text skills the master stores, T81, so skill entries no longer come only from the node: the node still builds the catalogue and decides, and every rule in this row is about skill folders): `SKILL.md` folders the node finds every agentic turn in the session repository's `.agents/skills` and `.claude/skills` and in the node owner's roots, listed to the model and loaded by the `skill` tool, are a channel for repository content and for the owner's files: a cloned repository or a prompt-injected agent plants a skill folder or `SKILL.md` that is a link to a key outside the repository or into the data directory, a FIFO, a flood of skills or a huge description to fill the context, a skill named like the owner's own (`deploy`) to replace it, front matter that claims to widen the agent (`allowed-tools`, `hooks`, `` !`cmd` ``), a `file` argument (`../../.ssh/id_ed25519`) or a link inside a skill folder that leads out; and on a node other people's chats use, the owner's home skills (`~/.claude/skills`) become readable by them

## Mitigation

**No more authority than `AGENTS.md` (T44), so no trust step of their own:** the instruction files of the same repository already reach the model in full every turn without one, so a per-repository trust decision for skills alone would gate the smaller channel and leave the larger open; the node owner can turn repository skills off (`[skills] repository = false`) or all skills (`denied_tools = ["skill"]`). **Read with T44's rules** (`harness_tools::inside::read_inside`, now shared by both): a regular file whose real path is inside its bound and in no protected folder, opened `O_NOFOLLOW \| O_NONBLOCK`, checked again on the descriptor.
A repository root and each skill folder in it must lie inside the repository (inside the session folder for the session folder's own `.agents/skills`, which the agent can write); a skill's `SKILL.md`, and every `file` the tool reads, must lie inside that skill's own folder (a relative path with no `..`, not absolute); a node root's skill folders may be links anywhere outside a protected folder (the owner made them).
Discovery reads at most the first 16 KiB of each `SKILL.md` and 1,000 entries per root, after the instruction files and under a 5 s limit of its own (a slow skill folder costs the list, never `AGENTS.md`: review S3).
**Nothing runs:** only `name`, `description`, `disable-model-invocation` and `user-invocable` (which only hides an entry from the composer's `/` menu, X.65) are read from the front matter (YAML through the workspace's `serde-saphyr`, and, when that fails, `key: value` lines split at the first `": "`, which is what other harnesses accept: review S1); every other key is ignored, no `` !`cmd` `` is expanded, and a script a skill names runs only through `bash`, its execution mode and its approval.
**Bounded text:** a name is 1 to 64 of `[A-Za-z0-9._-]` (a given name that is not, a direction override included, gives way to the folder's name; a folder name that is not refuses the skill); a description is made one line (controls and breaks to spaces, invisible characters dropped) of at most 1,024 characters; the catalogue holds at most 150 skills and 8,000 bytes (about 2% of a smaller known window, never below room for the lead, its notes and about ten shortened lines: review S6), shortening descriptions to 120 characters before leaving skills out, with a note, and names the folders whose `SKILL.md` was refused (names only); a body or file is cut at 24 KiB with a note.
The catalogue rides at the end of the instruction files' block, quoted under the harness's line (T43), so it is never the person's words or URL provenance (T22); the body is a tool result.
**Names:** the node owner's roots come first and the first of a name wins, so a repository cannot replace the owner's skill; the shadowed one is logged.
A manual skill is loaded only in the turn whose person's own message starts with `/name` (never a delegated task or a callback turn: review S5).
**The shell:** a session whose agent has the tool gets each existing `[skills] roots` folder (its real path, so a root that is a link is bound as its target), and a node skill folder that is a link out of its root, read-only in the shell's file view and Landlock rules, bound by its identity as a `[sandbox] read` entry is (`Grants::read_identified`; one replaced by a link since discovery is left out, one swapped after the look refuses the command, one holding or inside the data directory is never granted), so a skill's scripts run in a sandbox chat (review S2); a session without the tool gets nothing of them.
Tests: `tools/tests/skills.rs` (discovery, precedence, links out of the root and the skill folder, a FIFO, bad front matter, a bidi name, a protected folder, the caps and their notes, `file` by `..`, absolute path and link, a `SKILL.md` swapped for a link after discovery, a manual skill), `node/tests/skills.rs` (the request the provider gets; only agents with the tool, a sub-agent included; `repository = false`, `denied_tools`; `/name`; a delegated `/name` invokes nothing), `node/src/instructions.rs` (`a_skill_timeout_keeps_the_files_and_sets_no_catalogue`), `cli/tests/skill_roots.rs` (in real bubblewrap: a root's script runs, nothing there is writable, a session without the tool sees none), `agents/tests/agents.rs`; the review's probes are regression tests in `tools/tests/skills.rs`. `/compact` is a built-in composer command (X.20, T64), so the name is reserved (`harness_tools::skills::RESERVED`): a skill called `compact` is still listed and loads through the tool, but `/compact` does not invoke it (test `a_built_in_command_name_invokes_no_skill`).
**Residual:** skills are meant to be followed, so a hostile repository's skill steers the model as its `AGENTS.md` can, inside the approval mode and the sandbox; a node's skill roots are readable by every session on the node whose agent has the tool, through the tool and now through its shell, other people's chats included (documented; `roots = []` for a shared node), except that since X.34 a workspace can keep a skill (by name) for some of its agents: the others' sessions lose it from the list, the tool, `/name` and the shell's grants (T80); the default is still every agent of every workspace; the line-by-line fallback reads front matter YAML would refuse, so a malformed file yields a skill with whatever its `description:` line says; the catalogue is re-read every turn and sent again only when it changed (about 25 tokens a skill, up to about 2k; X.1, T52); a loaded body is summarised away by compaction like any tool result (the summary is told to name skills still followed, so the agent reloads them; not checked with a real model); hidden characters in a body reach the model as in T43.

**The composer's `/` menu (X.65)** lists names and descriptions the same node discovery found, for the chat's owner only, through `session.skills_menu`: the master takes the session from the route (`visible_session`: another member, a server admin and a workspace admin get the 404 of an unknown chat, and the node is not asked), resolves the chat's own agent itself (the page names nothing), and the node builds the list with the turn's own checks (`skill_on`, `[skills] repository` and `roots`, `denied_tools`, the agent's deny lists, the 150-skill and 16 KiB-of-front-matter bounds, links and regular files), so the menu offers nothing a turn would refuse.
It reads front matter only, never a body, starts no turn and appends no event; two answers at a time on a node and one waiting place per account on the master.
Repository text reaches the page as bounded inert text: names pass the skill-name rule at the node, the master and the page (a name with a space, slash, control or bidirectional character, markup, a built-in's name or a duplicate is not listed), descriptions are one line of at most 200 characters, drawn as text with hidden characters shown as codes.
`user-invocable: false` only hides an entry from the menu; the model's list and `/name` do not change.
Choosing an entry edits the composer's text and nothing else.
Tests: `tools/tests/skills.rs` (`the_menu_*`), `node/tests/skills.rs` (`the_menu_*`, `a_hostile_repository_gets_a_bounded_inert_menu`, `an_unknown_chat_has_an_empty_menu_*`), `master/tests/it/skills_menu_http.rs` (owner only, 404 for an admin, a hostile node's answer bounded again, an old or away node, busy, the waiting places), `master/src/skills_menu.rs`, `web/src/components/slashmenu.test.tsx`, `web/e2e/slash-menu.cjs`.
