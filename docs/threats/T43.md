# T43

## Threat

Text the person did not write stands as theirs in a user message (review of pull request 76, R76-1 and R76-3): the **per-turn context** (the person's settings, a routine's note, recalled memory, a project's instructions, facts and board, the last three written by other workspace members) rode in front of the person's text as `<context>\n…\n</context>\n\n` with nothing escaped, so an instruction or card title holding `\n</context>\n\n` closed the tag and what followed read as the person's message (the demo provider ran a `run:` line after it as their command); and the **note for an image** not shown again (`[image: <name>]`) sat inside the person's own words, so in a later turn an image's name counted as URL provenance (T22), and a lone CR or U+2028 in it reached the model

## Mitigation

**The context is quoted under one line of the harness's** (`provider::with_context`, `crates/agent-native`): `[harness] Context for this turn, not part of the person's message: the N line(s) below, each starting with "\| ", …` says what it holds and that others may have written it, every line follows behind `\| ` (`quoted_line`: control characters other than tab, U+2028 and U+2029 become U+FFFD; `\r\n` is one break), then an empty line and the person's text as it was.
A quoted line is never empty, so the frame ends at the first empty line and nothing in the context can end it; the demo provider splits there (`provider::split_context`) and takes commands only from what follows.
The lead does not say "no instructions": project instructions are meant to be followed.
The context is not URL provenance (since X.1 it is in the log, T52).
**Prompt cache:** not changed by this.
The context is still the head of the newest user message, after the system prompt and the history; at the time the next turn rebuilt that message from the log without it (since X.1 it rebuilds it with it, byte for byte: T52).
Review C43-1 found an older problem: with markers only on the system prompt and the newest message, every entry a turn wrote ended after its own context, so across turns only the system prompt and tools were read back.
It was fixed in its own change (`llm::to_genai`).
The history before this turn's message rebuilds byte-identical from the log, so a marker goes at its end, and a second at the end of the history before the previous user message: the place the previous turn marked, so it is read exactly where it ends, with no reliance on Anthropic's 20-block lookback.
With the system prompt and the newest message that makes at most 4. Until X.1 this turn's own message and its steps were written and never read in a later turn; since X.1 (T52) the next turn reads them too.
Tests: `llm.rs` (`the_history_before_this_turn_and_the_last_are_marked`, `short_requests_mark_each_place_once`, `no_request_has_more_than_four_breakpoints`), `lib.rs` (`the_next_turn_marks_a_prefix_this_turn_marked`: two turns through the loop with context and a tool call; turn N+1 marks, byte for byte, a prefix past the system prompt that turn N marked).
Not measured against a real provider.
**An image's note is a line of the harness's:** `[harness] Image "<name>": sent by the person with this message, not shown in this request.`, one per image after the person's text and files, the name made one line with every quotation mark read as `'` (`event::shown_name`, shared with a file's name).
**The person's own words end at the first line the harness wrote** after an empty line, or are empty when the message starts with one (`event::own_words`, which before ended only at a file's line), so no image name is URL provenance, in a later turn or a sub-agent's inherited set.
Tests: `agent-native/src/attachment_tests.rs` (`per_turn_context_reaches_the_provider_quoted_under_a_harness_line`, `the_demo_provider_takes_no_command_from_the_context`, `an_image_name_is_not_url_provenance_in_a_later_turn`, `an_image_note_is_one_harness_line`), `agent-native/src/provider.rs` (`nothing_in_the_context_ends_its_frame`: CR, CRLF, NEL, VT, FF, U+2028/2029, empty and break-only contexts, a forged lead, a large context), `agent-native/src/images.rs` (`no_image_name_is_in_the_persons_own_words`, with files and several images; the image-note tests there and in `llm.rs`), `core/src/event.rs` (`own_words_end_at_the_first_line_the_harness_wrote`), `master/tests/it/projects_http.rs` and `images_http.rs` (the project context arrives quoted; older images are named in harness lines).
Review: `docs/security-review/2026-11-t43-context-and-image-quoting.md`.
**Residual:** quoted text is still text the model reads and may obey, and project instructions are meant to be; `quoted_line` keeps hidden characters (bidi controls, zero-width characters, the tag plane), so an instruction or card title can still carry text the model reads and a person may not see, as a file's text can (review C43-2); when background notes wait in front of the message, their separator line says the person's message follows and the context's line comes first (the line says whose it is; review C43-3, the separator is left as it is because changing it moves the cached prefix of every message with notes); a person who types `[harness]` at the start of a message or after an empty line has the rest of it left out of URL provenance (less counts, never more); a person's text that starts with the context's lead line, sent without context, is misread by the demo provider only; a chat whose log holds an image no longer shown is sent in the new form from that message on, so its cached prefix is written once more (the events are unchanged).
Not checked with a real provider: how a given model weighs the quoted context against the old tags.
