# T14

## Threat

Model output (possibly steered by injected web or repo content) phishes, exfiltrates or poses as the harness through what the chat renders

## Mitigation

No model HTML, scripts, iframes or remote images; links show their real host (with the port when it is not the scheme's default) and odd ones need a confirm with the full URL; a link to another port, scheme or loopback name of the app's own machine is another server (the agent may have started it), so it always shows its host and port marked "another server on this machine, not this app" and always asks (Gate 3 fix review 2, W-2, `leavesApp` in `web/src/md/links.ts`); chat titles, search snippets, node names, tool names, agent-published file names and a node's error and output text show hidden characters as `<U+…>` codes outside Markdown too (W-3; titles and names keep the emoji joiner); an in-page `#` link works only between one message's own footnotes and their references (ids prefixed per message, `m<n>-fn-…`, so they never collide and a link cannot reach an app route, a button or field id, or another message; anything else is text: audit L14, `web/src/md/anchors.test.tsx`); `ui:` blocks are validated in Rust and drawn from the stored spec in a "from <agent>" frame; secret-asking questions and fields are refused; answers carry ids, never model text; the node checks every answer against its log.
