# T34

## Threat

The next person on a shared browser reads what the last one typed and never sent, or an incognito chat's words outlive it on disk (audit L14)

## Mitigation

The reply box keeps its unsent text in `localStorage` under `harness.draft.<user id>.<chat id>` (`web/src/lib/drafts.ts`), so one account never reads another's; a question or form card keeps its answer in `sessionStorage` (`harness.ui.…`, `ui/Input.tsx`).
**Sign-out clears them all, whoever's** (`App`: logout, any 401, a load that is not signed in; a socket closed with 4401 makes the shell check `/api/me` and sign out if the login is gone), together with the other traces that are the user's: recent folders, routine test events, Media picked for the next chat.
Theme, accent, backdrop, notification and sidebar layout preferences stay (no content).
**A chat's draft goes with the chat:** deleted here (`DeleteChat`, after the server's OK) or elsewhere (each chat-list load asks `GET /api/sessions/{id}` for drafts of chats it does not list, since they may be in another workspace, and drops the draft on 404).
**An incognito chat has none:** the box keeps no draft until the chat is known not to be incognito, a draft it had is removed, and its cards keep no answer.
Every storage read and write is guarded, so a private window, blocked or full storage only costs the draft.
Tests: `web/src/lib/drafts.test.ts`, `components/conversation.test.tsx` (drafts), `app.test.tsx` (sign-out), `live.test.ts` (4401), `ui/inputs.test.tsx`.
**Residual:** a browser that is closed without signing out keeps the drafts until the next visit there finds no login (then they are cleared) or the same user signs in; a card answer for a deleted chat stays in that tab's `sessionStorage` until the tab closes or the user signs out; the 404 check costs one request per draft of an unlisted chat on each chat-list load.
Anyone with the signed-in browser profile reads everything (out of scope, as for any web app).
