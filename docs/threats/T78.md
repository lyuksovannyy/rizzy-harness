# T78

## Threat

**Agents change a project's task board** (ADOPTION_PLAN X.32, README "Agents on the board", docs/projects.md "Task board"): `board` lists a project's board to an agent, `board_edit` adds, moves and appends notes to cards.
The board is shared by every member of the workspace and its text reaches every member's turns (T20).
Abuse cases: a prompt-injected or hostile agent (a) reads or changes another project's board, (b) changes a board its person may not change, or in a turn its person did not send, (c) learns the title of another member's chat through a card link, (d) erases or rewrites what people wrote, or writes lines that read as another agent's or a person's, (e) floods the board, (f) plants text that poses as the harness's own lines for other members' agents, (g) a compromised node forges requests for a session it does not run or another user's, (h) a resent message adds a card twice

## Mitigation

**Nothing in a request names a place**: `board.request` carries the session id and what to do; the request type rejects any other field (`harness-protocol` and `harness-core` tests).
The master takes the project from the session's own row (a sub-agent's: its parent's, same node and owner), the person from its owner, and refuses a session the asking node does not run (`recall::sessions`), a temporary chat, a chat outside a project, a node without the `board` capability (a).
Changes need the owner's "may manage projects" (`settings`), the HTTP routes' own check (`projects::may_manage`), read again for every request, so a role lowered mid-turn is refused (b).
Changes only in a turn the owner sent signed in (`by_owner`) or in a run of the owner's own routine (the owner, 2026-11-18: "Routines may change"): the routine runner passes the run id and `Master::prompt` checks it against the master's own record (the run active, its chat this chat, its routine the owner's), never anything the node or the model says; an API-token turn can only list (b). `Master::prompt` withholds `board_edit` accordingly and both tools from untrusted (webhook) and callback turns; each request is checked against what the turn's log says was withheld, against the callback mark, and against the turn's agent's own tool list (a sub-agent: its own switch, its parent turn's withholding, its changes on the parent turn's cap). `list` shows a card's chat by title only when the asking chat's owner owns it, otherwise "another member's chat" with no id or title (T10) (c).
No delete and no overwrite: `add` makes a new card, `note` appends, every line of it marked `[agent <name>]` (brackets dropped from the name), and is refused, never cut, past the card's 4,000 characters (d). 10 changes and 20 lists per turn (sub-agents' included), 4 calls at once per node, the board's 500 cards (e).
What `list` returns: every name (project, column, title, agent, chat title) is a JSON string inside a line the harness writes, so a `"` cannot end it; notes are quoted line by line under a harness line saying it is data; the answer as rendered stays below the tool output cap, ending on a whole card (f; the same frame as recall hits and attachments).
The master's secrets are scrubbed from titles, notes, column and project names and chat titles it returns.
A repeated request id from a node gets its first answer and changes nothing again (only once the node's call slot was taken, so a busy refusal is not cached); the node never resends a board request (h).
Each change is an audit line `board.agent` with ids only, naming the routine and run in a run's chat (g, after the fact).
Plan mode refuses `board_edit` (it is not on the read-only list);
Ask asks before it.

## Column 4

A person who may manage projects is the authority, and their agent acts with it: an injected agent in such a person's chat can add up to 10 misleading cards or notes per turn, and move cards, also into a done column, which hides them from every model's per-turn board line (nothing undoes a move but a person).
A routine changes the board with nobody watching, bounded by the per-turn cap and the routine's own schedule.
Planted text in a card still reaches other members' agents as quoted data (T20 residual: a model may be swayed by what it reads).
The untrusted, callback, owner and routine gates and the per-turn cap rest on the node's own `turn_started` (its turn id, its `withheld`, its cause): a compromised node can lift them for its own sessions, within the owner's permission (recall has the same design, T55).
The per-turn counts live in the master's memory: a restart, or more than 4,096 tracked chats, resets them.
A node that times out after 20 s tells the model the change may have been made; a model that retries anyway with a new request may add a second card (dedupe is by request id, not by content).
The agent's mark on a note, and the UI's "Noted by an agent" (a text match), are plain text a person can also type.
Notes appended by an agent do not record which chat they came from.
An agent with the Board switch counts as one that changes things by its definition: as a sub-agent it is not put on the small model even where `board_edit` is withheld (plan mode's delegate check does see the narrowed spec).
