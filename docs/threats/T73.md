# T73

## Threat

**The model's thinking is kept and sent back** (ADOPTION_PLAN X.25, README "Thinking"): each step's thinking is recorded with it (`assistant_message.thinking`) and later requests send it back as each provider needs. (1) A signed block changed, reordered, partly dropped or sent after its prefix changed: Anthropic refuses it (400 "thinking blocks cannot be modified", "bound to a different conversation") or, on some models, the model reads reasoning about content that has since changed. (2) Thinking of model A sent to model B or provider B. (3) A secret in thinking: the scrubber changes model text before it is stored, and a changed signed block is refused. (4) A provider that refuses the replay every time wedges the chat (the lesson of T71), or a refusal of something else withholds the thinking. (5) Size: a hostile or broken provider sends megabytes of thinking; a long tool loop with large signatures reaches the provider's overflow instead of our shortening; the loop holds every step's. (6) Rebuild differs from live (T59). (7) The summariser, hand-off notes, search, export, a browser or another user read it; a malformed payload from a node breaks the chat page.

## Mitigation

(1) **Rule, from the documentation** (fetched 2026-11-16, platform.claude.com "Thinking", "Preserved thinking / Prefix checks"): "within a tool-use turn, pass thinking blocks back", "across turns, pass everything back" (recommended), "outside tool use, omit prior turns' thinking, but not a block between two that you keep"; blocks "complete and unmodified", `redacted_thinking` kept in place; the prefix check fails "if `system`, `tools`, or an earlier message changed after Claude produced a block", cache markers and key order do not count; blocks may be left out as "the oldest, the newest, or all of them, but not one in between".
Encoded once, in `llm::thinking_parts`, `provider::settle_thinking` and `ModelRouter::own_thinking`: a step's `signed`/`redacted` blocks go back in their order, in front of its text and calls, only while the SHA-256 of what the request sends before them (tools, then each message's role and content, cache markers left out: `llm::Prefix`, computed only for Anthropic requests that hold signed blocks) equals the `prefix` recorded with them.
The prefix holds every block sent before a block when it was made, so a block whose earlier blocks are no longer sent is not sent either; one made after an earlier step's thinking was left out is valid and goes.
**The gap rule** (review of PR 137, r3): a step whose blocks were never sent (recorded `unsent`: a block after the step's text or a tool call, which genai would reorder; a scrubbed or oversized signed block; a model refused earlier) is "a block between two" the provider made, so no later signed block of that model is sent in any request (`settle_thinking`, also in the request builder); its prefix would not show the gap.
**Its cost:** on the newest Claude models (Opus/Sonnet 5.5, Fable) a progress update is a thinking block before each tool call after the first in one answer, so every step with two or more parallel calls is out of order, and the first one ends sending thinking back for the rest of the chat.
Parallel calls are common in coding turns (several reads at once), so on those models thinking is likely sent back only until early in the first turn; from then on the requests are main's (none).
That is the honest behaviour until genai can send blocks in place (or a live check shows Anthropic accepts the gap: then `settle_thinking` goes); on models without progress updates (4.x, Haiku) answers lead with their thinking and nothing is lost.
Earlier turns' thinking is sent too (the documented recommendation; dropping it would rewrite the prompt cache).
OpenAI-compatible: the plain text goes back as `reasoning_content` (DeepSeek "Thinking mode": with `tools`, "must be fully passed back … in all subsequent requests", else a 400), scrubbed or cut if it had to be (nobody verifies plain text; leaving it out would break such a host for the rest of the chat: review r2). (2) `ModelRouter` passes a request only its own prefixed model's thinking, so neither another model of the same provider nor another provider ever gets it; a fallback starts without; each API takes only its own kind of block. (3) `bound_thinking` scrubs every part, signatures and redacted data too; a signed or redacted block it changes is kept scrubbed for the person and the step is `unsent` (and starts the gap); plain text it changes is sent scrubbed.
A signature is the provider's encryption of the full reasoning: opaque, not a secret we hold, but it encodes whatever the model reasoned about, tool output included. (4) A request refused with 400, 413 or 422 (`may_be_the_images`'s class: not an overflow, not an unknown model) is resent, each time built from the refused request: without its thinking, then without the images `read` returned, then without both, as far as it holds them (at most three resends, `Resend::order`).
The first answered is the cause and only that is recorded before the answer: `thinking_withheld` (that model's thinking is not sent again in the chat: earlier steps' left out, later ones recorded `unsent`) and/or `images_withheld`; the rebuild applies the same at each record.
If none is answered the original error stands and nothing is recorded;
Retry replays the attempt (`thinking_loop.rs`, `thinking_review.rs` `r1_an_image_refusal_withholds_only_the_images`, `r1b`, `r4`).
Anthropic's adaptive thinking needs no block in a turn and the harness never sends manual `budget_tokens` (R8), so leaving them out cannot be refused for being missing.
**A Claude user's worst case after this change is one refused request per chat, then main's behaviour** (no thinking sent). (5) At most 256 KiB of thinking a step (`Thinking::MAX_BYTES`: a Claude signature is commonly 10 to 100 KB, plain reasoning of a long step tens of KB; megabytes are a broken provider): over it the first 16 blocks' text is kept, cut to 64 KiB, the opaque parts dropped, signed steps `unsent`.
The log grows by at most 256 KiB a step from thinking: 256 MB per 1,000 steps in the worst case.
Thinking counts toward the context estimate (its text, or 3/4 of its signature's length when more) and toward the protected tail; when a request is over the window's line, in-turn shortening first leaves out the signed thinking of every step before the tail, oldest first (`context_shortened.thinking`, no model call), then clears results and folds steps as before; plain reasoning text is never left out by that tier (a host that follows DeepSeek's documented rule would refuse every later request: re-check of PR 137, `thinking_recheck.rs` `a1_a_strict_plain_reasoning_host_answers_through_shortening`): it stays bounded by the 256 KiB cap and goes whole with its step when a fold removes the step, which the rule allows (`thinking_review.rs` `r5_large_thinking_is_bounded_across_forty_steps`, 40 steps with a 200k window: plain reasoning of 1.5 MiB a step, cut to 256 KiB, is bounded by folds, at most 0.59 MB in any request; signed blocks of 100 KB a step by the thinking tier; every request under the window; before the fix round, 62.9 MB and no record).
The loop keeps no thinking a request no longer sends (`shorten::drop_thinking`: a marker with no blocks), so its memory is bounded by the request's, as T71's image cache.
Genai still holds a whole answer's reasoning until its stream ends (the bound applies after). (6) The loop's conversation holds the step's thinking as the log stores it, settled and shortened the same way as the rebuild (`turn_compaction_review.rs` `rebuild_matches_live_with_thinking*`, which now also checks that shortening left thinking out; `thinking_loop.rs`, `thinking_review.rs`). (7) The summariser's transcript and hand-off notes never carry it, nor another agent's requests; search indexes only `text`; the Markdown export skips the row; browsers get each block's kind and text only (`RawEvent::for_browser`, the one way the master writes an event into a response: the events endpoint, the socket's catch-up and its live fan-out; re-check of PR 137: the live fan-out sent them before; the view's item holds no signature); both folds keep only well-formed blocks (a `null`, a number or a block without a type is dropped) and the row shows the first 64 KiB until asked.
Thinking is part of the chat, private to its owner like the rest of the log.
**Live (2026-11-16, the owner's router):** DeepSeek (`mistral/deepseek-v4-1-flash-1017`, with `reasoning_effort`) through the harness: each step's `reasoning_content` recorded, sent back on the next requests, the next turn's and after a restart, every request answered.
Contradicts its documentation: this host also accepts a tool loop with `reasoning_content` left out.
The router's Magistral, Mistral Small and GLM models send the same shape and accept it back.
**Residuals:** a resend that gets an error that is not a refusal (an overflow, an authentication error) reports the original refusal instead and the overflow path is not taken for it; a refusal costs up to three wasted requests; not tested by anyone: a fallback to another model mid-turn after the thinking tier fired, a restart in the middle of a turn (`/compact` after the tier is covered: `thinking_review.rs` `compact_after_the_tier_left_thinking_out`); nothing from Anthropic is verified live (the account answered "credit balance is too low" to every request): the signed-block path is proven only against local servers speaking the documented shapes; the gap rule may throw away valid thinking on the newest models (above); a restart in the middle of a turn was not run live; thinking is not streamed live; parallel answers keep none;
OpenRouter's `reasoning_details` and Gemini thought signatures are not kept.
