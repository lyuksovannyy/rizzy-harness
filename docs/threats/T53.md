# T53

## Threat

A turn's diff (X.12) shows file contents of a chat's folder to someone who is not its owner, carries the node's secrets or a file's content into a log, an event or the master's store, or lets a hostile repository turn the node's git into a command (a file named like an option, a pathspec glob, a filter), read outside the folder (a link to elsewhere) or exhaust the node (a 2 GB file, 50,000 changed files)

## Mitigation

**Owner only:** `GET /api/sessions/{id}/turns/{turn}/diff` passes the same visibility check as opening the chat (`visible_session`): another member, a workspace admin and a server admin get the 404 a chat that does not exist gets (T10); the turn id must look like a node's (80 plain characters), so nothing else reaches the node.
**No execution level is needed** (coordinator's decision, review D13): viewing a diff is a read like reading the chat's own events, and it starts no work on the node.
Its limit: a diff can show file content that was never in the chat's log (a file a command wrote and no tool read), so an owner whose level was lowered can still read what their past turns wrote in that folder.
**A view, never an event:** the master relays one `session.diff` to the owning node only, and hands the one `session.diff_result` that answers it, from that node only, to the waiting request (`crate::diff`); nothing is cached or stored, and no path or line is logged on either end; one account holds at most 4 of the master's 32 waiting places; the response is `no-store` like every `/api` answer.
The node appends nothing; its audit log records `session.diff` with the session id only.
The node's `SecretSet` scrubs every path, line, section title and error text, each whole before any cut (review D2), the rule events follow.
**The same confined git as undo:** the shadow repository, never the person's `.git` (R.1), cleared environment, overrides, the jail, attributes from the empty tree (no filter, driver or textconv runs), `--no-ext-diff --no-textconv`; the files compared are named after `--` with `--literal-pathspecs`, so an option-like name, a glob or `:(magic)` is a name; the patch's sections are matched to the raw rows by their full blob ids, never by a path parsed from a header; a link is its target text, never followed.
**Bounded:** at most 1,000 files listed (the rest counted), a side over 512 KiB named with its size, binary content named with its sizes, at most 4 MiB of blobs compared, 256 KiB of lines per file, 1 MiB per answer, lines over 2,000 bytes cut and marked while the rest of the file still shows (review D1), the serialized answer at most 2 MiB (the last files' lines, then names, go first), 20 s for the whole read (git killed with its process group), two diffs at once per node (a third refused at once) and 32 waiting on the master.
A pruned checkpoint, an unknown turn, a node that is away or too old: a sentence (409, 503), never a 500. Residual: the owner sees their own files, a `.env` the agent touched included (as `read` would show it); a node that lies about a diff only misleads its own owner, whom it already serves.
