# T65

## Threat

**Instruction files of subfolders** (ADOPTION_PLAN B.9, X.2; T44's neighbour for folders below the session folder): `web/AGENTS.md`, `crates/tools/CLAUDE.md`, loaded by the loop when the agent first works under that folder.
The same channel as T44, with more ways in: (1) a cloned or hostile repository plants one in any subfolder, as a link out of the session folder (to a key, the data directory), a FIFO, a huge file, thousands of them, a folder name with a line break or a quotation mark that forges a label or a harness line, or a secret in the text; (2) a prompt-injected agent writes one (`write web/AGENTS.md`, a `bash` redirection) and then obeys it in the same turn, before the person has seen what it did; (3) the loading breaks what T52 and T59 promise: a request the log cannot rebuild byte for byte (after a restart, in the next turn, a callback turn, after clearing or an in-turn or between-turns summary), parallel reads that add files in the order they finished, or earlier bytes rewritten so the provider's cache is lost; (4) a file the history says was sent is gone from the request after clearing or a fold, so the model works against rules it no longer sees

## Mitigation

**Read by the loop on the node with T44's rules** (`crates/agent-native/src/nested.rs`): only for a call whose result names the file it touched (`tool_call_finished.seen`: `read`, `edit`, `write`) or a file the person's message mentioned (T63), only the folders strictly between that file's real path and the session folder (none for a file outside it in outside mode, none inside `.git`), one file per folder (`AGENTS.md`, else `CLAUDE.md`, blank counts as none), through `harness_tools::inside::read_inside` with the session folder (a sub-agent's own folder) as the bound and the node's protected folders: a link is followed only to a regular file inside the session folder, the descriptor is checked again, a FIFO is never waited on, at most the cap is read; the whole look waits at most 5 s and not past the turn's cancel, and a look that did not end in time, at the turn's start or after a step, stops the looks for the rest of the turn (a hung disk costs one wait, not one a step).
A refused file is named with the reason.
**Text only, quoted twice:** each file is a section whose label line names its path in JSON quotation marks (line breaks escaped) and whose every line is indented by two spaces (the fix of PR 120), inside a block under the harness's line, every line behind `\| `; it is sent as a user-role message of its own, the root files' standing and no more (no trust decision, as X.2 dropped it for the root files and skills); it changes nothing the node decides and is never URL provenance.
Scrubbed before it is sent or recorded; a file whose path the scrubber would change is not loaded at all.
**Bounded:** one file at most half the total (16 KiB as sent, indentation counted, cut with a note to `read` the rest), all of them at most the smaller of 32 KiB and about a tenth of the model's known window, at most 16 at a time since the last summary; over a cap a file is named once a turn in a line of that turn, not loaded.
**The agent's own writes:** a file that changed during the turn (a path one of its `write`/`edit` calls wrote, or a modification or inode change time after the turn began less 50 ms for the kernel's coarse clock; the change time cannot be set back, so `touch -d` does not hide a command's write) is named, not taken, in that turn; a touch in a later turn takes it (the node takes the session folder's own file at the next turn's start: the same rule).
A later turn is not always one a person started or saw: a callback turn is one.
A sub-agent's turn takes nothing changed since the turn that delegated to it began (`TurnExtra::changes_since`, the parent turn's start, set by the node and passed down the chain), so a parent agent cannot write a subfolder's file and delegate into that folder to have it obeyed.
**Rebuilt from the log:** the files a step loads are recorded where they stand (`context_sent`, frame `step`, after the step's results and notes, in call order whichever call finished first) and rebuilt there by every later request; nothing earlier is rewritten, so the cache holds; at each turn's start every file the history holds is read again and, when it changed, sent once in that turn's opening with the harness's line saying it replaces the earlier copy, which leaves the rebuilt history (T52: one cache write, as for the root files); gone, withdrawn with a line; not read in time, kept.
Clearing touches only tool results; an in-turn summary keeps the step blocks verbatim; a summary of earlier turns inside the turn sends the files the turn's opening had again (a file kept only because its read timed out is dropped and reloads on a touch); after a between-turns or manual summary (T64) the files are gone with the history and the next touch loads them again (Claude Code, OpenCode and DeepSeek reload on touch after compaction: research/round1/claude-code.md 1154-1175, research/round2/opencode.agents.md 96-104).
A message the person sends meanwhile has its mentions' folders looked in right after it, before the next request.
Folders are looked in once a turn (a few `stat`s), nothing on the master.
Tests: `agent-native/tests/nested_instructions.rs` (each trigger, a mention and a queued message's mention, call order of parallel reads, a command's write with its time set back, a sub-agent and its parent's write, the independent review's attacks `r1`-`r6`: hostile folder names, a FIFO, a 50 MB file, where a replacement rewrites, an in-turn summary of earlier turns, change, deletion, the agent's own write and a command's change, the caps and the named-not-loaded lines, a link out, a link in, a linked folder in and out, a forged label, a secret, clearing and a fold, `/compact`, a restart, a sub-agent, a callback turn, no folder), `agent-native/tests/turn_compaction_review.rs` (`rebuild_matches_live_with_nested_instruction_files`: random steps over two turns with files appearing, changing and deleted, clearing, folds and summaries of earlier turns, every request rebuilt and compared), `agent-native/tests/parallel_review.rs` (`reviewer_parallel_stress_with_nested_files`), `node/tests/repo_instructions.rs` (a sub-agent through the node, a mention through the node).
**Residual:** as T44, the instructions are meant to be followed, so a hostile repository steers the model inside the approval mode and the sandbox; a file a step loads is the text at that moment, and a change later in the same turn waits for the next turn; a file system without inode change times (FAT stores none, and reports the modification time, which a command can set back) can make a command's change look old; a file saved in the 50 ms before the turn began waits one turn; a callback turn (nobody started it) takes a file the previous turn's agent wrote, as it takes the root files; a folder looked in once a turn misses a file made there later in that turn; a mentioned folder (not a file) loads nothing; after a summary the model works without a subfolder's file until its next touch there (an `edit` right after a summary, of a file it read before, goes out before the file is back), as in Claude Code.
