# T100

## Threat

**A person's request makes the harness write a file** (ADOPTION_PLAN X.60, README "Looking at a file").
The page sends a list of changes (a paragraph's tag or a cell's address, and text) for a Word or Excel file, and a copy with them is made: held on the master in a chat without a folder, written by the node beside the original in a coding chat.
The questions are who can ask, what the page can make the node write and where, whether a hostile file or a hostile helper, node or page can make it write something else or overwrite something, what the helper's and the node's words may leak, and what a flood of saves costs.

## Mitigation

**Who.**
Both routes are POSTs, so a cookie request must carry an allowed `Origin` (the guard of `auth.rs`: no `Origin`, or another one, is a 403), and the caller is resolved by `acting_session` (another person, an admin too, gets the 404 a chat that does not exist gets, T10; the API token that acts in another's chat marks it, T85).
A chat without a folder takes the checks of the preview in the same order (a plain top-level chat that is not temporary, the file a row of that chat's own log, the owner's blob, a Word or Excel name, 10 MB) and the coding route those of the folder preview (the agentic grant, not a plain or temporary chat, a path of at most 1,024 bytes); a sub-agent's chat, a coding chat on the plain route and the reverse, a file id of another chat and a planted row of another owner's blob are the same 404 and the helper and the node are never asked (`crates/master/tests/it/doc_page_edit_http.rs::nobody_else_saves_a_copy_and_a_cross_origin_post_is_refused`, `::a_planted_row_a_folder_chat_an_incognito_chat_and_a_sub_agent_are_not_edited`; `folder_page_edit_http.rs::nobody_else_saves_and_a_cross_origin_post_is_refused_and_the_node_is_never_asked`, `::a_plain_chat_a_temporary_one_and_a_bad_path_are_404_and_ask_nothing`, `::an_owner_who_lost_the_level_is_refused_and_the_node_is_never_asked`).
The coding route asks a sub-agent's chat of the owner as any other coding chat: it shares its parent's folder and the node reads under the session's own rules; another person's is the same 404 (`folder_page_edit_http.rs::a_sub_agent_chat_of_the_owner_is_asked_as_any_other`).
**What the request can say.**
Nothing names a destination: the body is `{path?, sheet?, changes: [{at, text}]}` with unknown fields refused (`deny_unknown_fields`, in the body, in a change, on the link and in the helper's request), at most 200 changes, a place of at most 64 bytes, a text of at most 80,000 bytes (20,000 characters) and all of it within the helper's header bound; each at its edge and one past it before the helper or the node is asked (`doc_page_edit_http.rs::the_bounds_are_checked_before_the_helper_is_asked`, `folder_page_edit_http.rs::the_bounds_are_checked_before_the_node_is_asked`, `crates/node/tests/folder_page_edit.rs::the_node_checks_the_bounds_again`, `crates/docs/src/edit/tests_page.rs::the_number_of_changes_is_bounded_at_its_edge`).
A place that is not a body paragraph's tag (`p<n>#<4 hex>`) or a cell address, the same place twice, and a text too long are refused per change, not by a panic (`tests_page.rs::a_change_that_cannot_be_applied_says_why_and_saves_nothing`, `::the_same_place_twice_in_one_request_is_refused`, `::a_cell_the_engine_refuses_is_said_so_per_cell`; `tests_fuzz.rs::random_page_changes_never_panic_and_never_hand_out_a_bad_file`).
**What it makes.**
What the page shows is what is written: the field starts from the preview's cleaned text, which drops invisible, direction and private-use characters, turns controls into spaces and an object into `[obj]`, and a cell's text is one line; writing that back would lose what the person could not see.
So the preview names no place for a paragraph whose cleaned text differs from the file's (`at` is empty) and marks such a cell `x`, and the helper asks the same question itself (`page::apply`: the same `faithful_text` and `faithful_cell`) and refuses the change as `not_editable` whatever the page sent; an object placeholder is never written as text (`tests_page.rs::a_paragraph_with_characters_the_page_cannot_show_is_not_offered_and_not_changed`, `::an_object_placeholder_is_never_written_as_text`, `::a_cell_shown_changed_is_marked_and_not_changed`, and with the real helper `crates/cli/tests/doc_edit.rs::a_file_named_as_the_other_kind_or_with_hidden_characters_is_not_changed`).
The gate is by the file's name and the edit by its content, so the request carries the kind the name says (`doc` or `sheet`) and the helper refuses a file of the other kind as `not_office` (a workbook named `.docx` cannot be edited under `doc_edit`'s say, nor a document named `.xlsx`; `tests_page.rs::a_file_of_the_other_kind_than_its_name_says_is_not_office_here`, the same with the real helper in the cli test above).
Each change is one of the edit tools' own operations, run by their own functions in the confined helper (T98), so a stale tag, a field, a link, tracked changes, a hidden, merged, array or shared-formula cell, a refused formula (`WEBSERVICE`, `HYPERLINK` not to http, a link to another workbook) and a part past its limit are refused as for the agent, and the output passes the same package check; a request applies all its changes or none.
A typed cell is decided in one place (`cell_value`): `1e999`, `0x10`, `007`, `1,200` and 16 digits are text, not numbers (`tests_page.rs::what_a_typed_cell_means_is_decided_in_one_place`).
A sheet is the place among the visible sheets, resolved in the helper, and refused when two sheets have one name (`::a_sheet_is_picked_by_its_place_and_a_bad_place_is_no_sheet`); a protected document or sheet is `locked` (`::a_protected_document_is_locked_not_damaged`, `::a_protected_sheet_is_locked_not_damaged`).
**What the node writes, and where.**
The node reads the source as the preview does (one function: the pinned folder, a sub-agent's own, links followed and judged, protected places, never outside the folder whatever `allow_outside_workspace` says, never inside `.git`, only a regular file opened without blocking, at most 10 MB), and every way of not reaching it is the one `not_found` (`crates/tools/src/folder_edit.rs::tests::every_way_out_is_not_found_and_writes_nothing`, `crates/node/tests/folder_page_edit.rs::paths_that_leave_the_folder_or_are_not_files_are_one_answer_and_write_nothing`).
The node decides whether to write at all: it needs `read` and the editing tool of the file's kind (`doc_edit` for .docx and .docm, `sheet_edit` for .xlsx and .xlsm) not denied by node.toml and offered by its backend, else the answer is `no_write` and nothing is written, and the capability is not announced where neither tool is on (`node/tests/folder_page_edit.rs::a_node_that_denies_the_editing_tools_or_read_writes_nothing`).
A chat's own approval mode does not gate the save: it is the person's own act, as an upload saved into the folder is.
The node's ceiling does: where node.toml's `max_approval_mode` is `plan` (which refuses every tool that changes something) the node answers `no_write`, writes nothing and does not announce `doc-page-edit`; `ask`, `ask_all` and `accept_edits` ceilings do not gate it (`crates/node/tests/folder_page_edit_save.rs::a_valid_save_writes_a_copy_and_the_gates_write_nothing`, with a request whose tag is the file's own, so that the gate and not a stale tag is what refuses it).
The copy goes beside the original, in the directory the person's path names, under a name the node makes (`<stem> (edited)`, then `(2)`), through the write side of the path policy and the create-only write of `doc_edit` (`create_free`): a temporary file in the directory published with a hard link that fails when the name exists, so an existing file or a link is never replaced or followed (a link to a file inside the folder is passed over, one that leads out is refused before anything is written) and a full or read-only disk leaves no half file (`tools/src/folder_edit.rs::tests::an_existing_name_or_a_link_in_its_place_is_not_written_through`, `::a_directory_that_is_read_only_is_no_write_and_leaves_nothing`; the real helper in `crates/cli/tests/doc_edit.rs::a_folder_file_is_changed_into_a_copy_through_the_node_helper`).
The copy is never over 10 MB.
The agent's table of files it has seen is not touched (the node's request has a context of its own), so the agent must read the copy before it edits it.
**What a hostile helper, node or page can say.**
The helper's own words may hold text of the file and never leave the helper's caller: each change's reason is one word (`ChangeWhy`), and the master turns it into a sentence of ours (`doc_page_edit.rs::sentence`); the node's answer is one word per change and one word of refusal; a refusal word a newer node has and this master does not is read as `unknown` and is a 502, never a broken link (`crates/protocol::doc_page_edit_wire_shape`).
An answer with more or fewer results than changes, a copy beside a refused change, no copy beside all ok, a copy over 10 MB, or a path from a node that is absolute, climbs with `..`, holds a control character or is over 1,024 bytes is a 502 or a refusal and nothing is stored or forwarded (`tools/src/folder_edit.rs::tests::a_hostile_or_confused_helper_answer_writes_nothing`, `doc_page_edit_http.rs::a_hostile_or_confused_helper_stores_nothing`, `folder_page_edit_http.rs::a_node_that_misbehaves_is_a_502_and_nothing_it_says_is_forwarded`); an answer from another node, or of the other kind of request, is ignored (`::one_at_a_time_and_a_wrong_answer_is_ignored`); a page that gives up frees the place and a late answer finds nobody (`::a_request_the_page_gave_up_frees_the_accounts_place`).
The page draws the saved path as text, puts it in the message only as a mention the composer reads back (quoted when it holds a space; none when it holds a quote, an `@` or a control character), and never as HTML (`web/src/components/docpreviewedit.test.tsx::the_saved_path_is_text_and_a_path_that_cannot_be_a_mention_is_shown_and_not_inserted`).
**Cost.**
A save takes the account's one helper slot on the master and the one place on the node that a preview takes (so a person's previews and saves together hold at most one of the helper's two places; a second is told to try again), and a chat without a folder's copy counts against the account's held files and quota as an upload does and is refused the same way (`::a_save_is_held_under_the_limits_of_an_upload`, `::the_account_quota_counts_a_saved_copy`).
The copy's name is the original's stem cut to leave room for ` (edited)` (and, for wide characters, within what a file system takes in a name) before the suffix is added, so the suffix always survives and the copy never carries the original's name (`harness_docs::name::edited_stem`; `folder_edit.rs::tests::a_long_name_keeps_the_suffix_and_never_names_the_original` at 91, 92, 100, 120 characters and a multi-byte stem).
A path a node names for the copy must also hold no invisible, direction or private-use character (category Cf, U+2028 and U+2029, U+00AD): the master answers 502 and the page does not put such a path in the message (`folder_page_edit_http.rs::a_node_that_misbehaves_is_a_502_and_nothing_it_says_is_forwarded`; `docpreviewedit.test.tsx::a_mention_is_the_path_as_typed_...`).
In a chat without a folder the held copy is an unsent upload: if the person leaves the chat before the message is sent it reaches no composer and expires with the other unsent uploads (the `[chat] incognito_ttl_minutes` age, 24 hours by default; its blob goes with the hourly storage sweep) and counts against the account's 20 unsent files and quota until then.
No log line holds a path, a change, a text or the copy's name; the node's audit line holds the session id only.
Known and plain: a workbook cell has no hash, so a cell the agent changed since the preview is changed to what the person typed in the copy (the original is not touched); the node's one place is shared by all accounts on that node, as for the preview; a path that is a link inside the folder to another file inside the folder is read and the copy goes beside the link's name; a copy a person makes between turns is in the next turn's `before` checkpoint like any file the person adds by hand, so the next turn's diff does not show it (docs/undo-and-stash.md, row 3; not run).
