# T98

## Threat

**An agent edits a Word or Excel file somebody else wrote, and the result is a new file the person opens** (ADOPTION_PLAN X.57, README "Documents the agent makes").
The input is hostile: a zip bomb in a part the edit never touches, a `DOCTYPE` with an external entity, names that make our reader and Word disagree about which entry is meant (a repeat, a repeat by letter case, one with a control character or `..`), a part that is not UTF-8, an encrypted or signed or protected file, a relationship that points outside the package, a part so large or so deeply nested that holding it ends the process, a paragraph that holds hidden text the person cannot see and the model must not be able to match, a formula that sends the sheet away when opened, an edit that corrupts a file so Word offers a repair (runs split by Word, a shared formula's followers, a calculation chain that names a cell that is no longer a formula, rows out of order), and a prompt-injected model that uses the tool to put its words in a person's document.
The tools also read a person's own file back to the model, whose text, sheet and name are untrusted.

## Mitigation

**The file is parsed only in the confined helper.**
`rizzy-harness doc-edit` is `doc-text`'s sibling: Landlock with no filesystem access and no TCP, an address-space cap, no core dump and not dumpable, an empty environment, one thread, the same supervisor (two helpers at once on the server and on a node, one per account on the server, 20 seconds, stdout capped at the largest file and a header, the process group killed on timeout, excess output and a dropped call).
The master spawns it for a plain chat and a node spawns its own binary for a folder chat; neither parses the file in its own process, and a node or server that cannot confine the helper (no Landlock, a kernel before ABI 4) refuses and says so (`crates/cli/tests/helper_confinement.rs` proves, with the helper's own probe, that after confinement it cannot open a file that exists, cannot connect to a port that listens, holds a core limit of 0 and is not dumpable, for `doc-edit` as for the others; `crates/cli/tests/doc_edit.rs`, `crates/master/src/pdf.rs::tests::an_edit_helper_has_the_same_bounds`, `crates/tools/src/doc_helper.rs::tests`).
**One part changes; every other entry is copied as it was stored.**
A part is patched with a streaming `quick-xml` pass (no new crate: already pinned for the reader of T96) that records the byte range of what changes and copies every other byte of the part as it came, so what Word wrote (the order of attributes, `<a />`, namespace declarations, `mc:Ignorable`) is not normalised away; every other zip entry is copied as its original compressed bytes with its CRC, sizes, method, timestamp and place in the order, never inflated, so a bomb in an untouched entry is copied and costs nothing (`crates/docs/src/edit/tests.rs::untouched_entries_are_copied_as_their_original_bytes`, `::the_patcher_changes_only_its_ranges`; `crates/cli/tests/doc_edit.rs::a_bomb_in_an_untouched_entry_is_copied_not_inflated` for the helper, 300 MiB of zeros).
Elements are matched by local name and by the namespace the root binds the prefix to, and a part that rebinds that prefix below the root is refused.
**What the pass refuses.**
A `DOCTYPE` (no entity is ever defined or expanded), a part that is not UTF-8 or declares another encoding, nesting past 64, more than four million events, a part over 8 MiB (10 MiB after the edit, counted as the patched part is written), an encrypted entry, a method other than stored and deflate, a link or special file in place of a part, sizes of 4 GiB or more, a package of more than 4,000 entries, names that are not UTF-8 or that this reader would show differently, duplicate names and names that differ only by letter case, `_xmlsignatures/`, document protection with enforcement on (`word/settings.xml`), a protected sheet, hidden sheets (`::a_package_an_edit_cannot_keep_faithfully_is_refused`, `::the_scan_refuses_what_it_cannot_keep`, `tests_docx.rs::protected_signed_and_foreign_documents_are_refused`, `tests_xlsx.rs::a_protected_sheet_and_a_macro_workbook_are_handled`).
**Hidden content is not addressable.**
Hidden runs (`w:vanish`), tracked deletions and field codes are not in the text a view shows or a `find` matches and are copied through untouched; a paragraph that has them cannot be `set_text` or deleted; hidden rows, columns and sheets of a workbook are left out of the view and refused as targets (`tests_docx.rs::hidden_and_deleted_text_cannot_be_matched`, `::set_text_refuses_what_it_would_destroy`, `tests_xlsx.rs::what_excel_keeps_as_one_is_not_overwritten`).
**An edit that would corrupt the file is refused, not attempted.**
A paragraph's visible text is read across runs and the replacement goes into the first run, whose properties stay; a match that crosses a field, a tab, a line break, a picture, a link, a tracked insertion or a content control is refused; a text the model writes goes through `xml::clean` and `xml::text`, and a `w:t` that gains leading, trailing or doubled spaces gets `xml:space="preserve"`; `w:sectPr` is never deleted or moved, nor the last paragraph of a cell or the body, nor a paragraph with a bookmark or a comment anchor; an inserted heading uses the document's own style found by name, a list item copies the anchor's `w:numPr`, links, images, tables, quotes, code blocks and raw HTML are refused (they need a part or a relationship an edit does not add); no part is added to an existing file.
In a workbook a cell keeps its style index, text is written as an inline string, an ISO date goes only into a cell with a date format and in the workbook's own date system (1900 or 1904), rows and cells stay in order and `dimension` and `spans` stay right, the first cell of a shared formula, a cell inside an array formula and a merged cell but the top-left are refused, a formula passes the deny-list of T97 as a whole, `fullCalcOnLoad` is set and the calculation chain is removed with its content type and its relationship when a formula cell is added, removed or overwritten, tables, filters, validations, conditional formats and pivot tables are named in a warning and not extended, and `.xlsm`'s `vbaProject.bin` is copied like any entry and never read (`tests_docx.rs`, `tests_xlsx.rs`).
**All or nothing, and read back.**
Every edit of a call applies or none does, and the result says for each edit whether it applied or why not.
After an edit the helper reopens its own output with the same reader and refuses to hand a file out unless the part is well-formed (attributes parsed), the paragraphs or cells read back as the edits say, every relationship target and content type is present (what the input already lacked is not counted against the edit) and rows and cells are in order; this is not Word's validator and catches our own bugs only (`docx.rs::edit`, `xlsx.rs::edit`, `check.rs`).
**Bounded.**
At most 200 edits, 20,000 characters in any one text, 100,000 bytes of Markdown in one insert, 10,000 cells in one `set` or `append_rows`, 1 MiB of request, 10 MiB of file, and the view at most 30,000 bytes in pages of at most 400 items (`tests_docx.rs::the_edit_calls_bounds_hold_at_their_edge`, `tests_xlsx.rs::the_sheet_edit_bounds_hold`, `doc_edit.rs::the_largest_part_is_edited_inside_the_memory_cap`).
A plain chat counts like `doc_create`: 60 calls a turn, 240 in ten minutes, one at a time, the same per-node limit, and 100 made files.
**The input is never overwritten, and the new file takes the paths of `write`.**
In a folder the result is created by the create-only write of T97 (the path policy of `write`: the folder, the protected places, `.git`; the approval path; the undo record; a name that is taken is passed over), beside the original as `name (edited).ext` or at `save_as`; `denied_tools = ["write"]` of a node turns the two editing tools off with the creating ones; the viewing tool reads the file under the policy of `read` (`crates/tools/src/office_edit.rs::tests::a_folder_file_is_viewed_quoted_and_edited_into_a_new_file_beside_it`, `::the_path_policies_hold`).
In a plain chat the request carries only the id of one of the chat's own files (a file the chat's log or its uploads name, the owner's blob, 10 MiB at most; the scope is taken from the session alone) and the result is a new made file (`made_http.rs::an_edit_of_the_chats_own_file_is_kept_as_a_new_made_file`, `::an_edit_names_only_this_chats_own_files`, `::a_failing_helper_keeps_nothing_and_says_why`).
**What the model reads.**
Everything the helper says (the view, each edit's outcome, the warnings) reaches the model as lines quoted with the output mark, one line each, since it may carry text, a table's name or a sheet's name from the file (`office_edit.rs::tests::a_plain_chat_sends_ids_and_edits_and_quotes_what_comes_back`, `::a_refused_edit_writes_nothing_and_says_which_and_why`).
Known and accepted:
- Nothing here ran in Word or Excel: the tests read every file back with our own reader only (the helper's own check is the same reader); the samples are for opening in the real programs before merging.
- An inserted paragraph copies the anchor's spacing, indent and alignment and its style unless the anchor is a heading or a list item, not its run properties: it takes the style's.
- A paragraph in a content control, a nested table or a text box is shown and not editable; tracked changes are not produced (an edit is a plain change), comments, images, charts, number formats, new sheets, row and column insertion, new lists and links in an existing file are not done.
- A document with the 1900 leap-year quirk before 1 March 1900 is not written as a date.
- On a kernel without Landlock (or before ABI 4) the helper refuses, so a macOS node or an old kernel cannot edit; reading a document has the same limit.
- With `AcceptEdits`, an edit without `save_as` has no path in its call to approve (the result lands beside the original), so it asks.
