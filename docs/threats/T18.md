# T18

## Threat

A compromised node or steered agent uses publishing to fill the master's disk, pull secrets, plant files in another user's artifacts, or slip files past checks; a compromised master uses stage ids to read or delete node files

## Mitigation

Publishing is a mutating tool (approval in `ask`) and node.toml `[artifacts] enabled` can turn it off; node-side confinement (session cwd or workspace roots, never the data dir, `O_NOFOLLOW` + fd re-check, regular files only, secret-like names refused or skipped); a staged copy; stage ids resolved through the node's own index, never as paths; pull-only, windowed transfers started by a validated event from the owning node and sent only to nodes that announce the `artifacts` capability; owner, workspace and project from the publishing session's own row, never `parent_id`; the path a version was published from (`meta.source_path`) is shown to the artifact's owner only, never to the members of a shared artifact (audit L5); exact size and sha256; quotas, a free-disk floor, per-node pending and hourly caps, and per-owner lineage caps.
Details: [docs/artifacts.md](docs/artifacts.md).
