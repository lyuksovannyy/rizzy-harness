# T86

## Threat

**Cloning a forge repository into a new project's folder** (ADOPTION_PLAN X.27 step 3; README "Cloning a repository"; `crates/master/src/http/projects/clone.rs`, `project_folder.rs`, `forge_repos.rs` (`repo_url`, `get_one`), `crates/node/src/forge_clone.rs`, `policy.rs` `[forge]`, the `project.clone` message): a person's forge token leaks (to another host on a redirect, into `/proc/<git>/cmdline` or `environ`, into the clone's folder or `.git/config`, a log line, an event, an audit line, an answer, the node's or master's data directory), is used by someone other than its person, or the clone becomes a way to run code, read local files, fetch from another host or fill a node's disk

## Mitigation

**Whose token:** `POST /api/projects` with `connection_id` + `full_name` takes the connection by (caller, id): another member's, an admin's or anyone else's id is 404, the API token 403, a disabled account 401; a host the server no longer allows 409; the name must have the shape of that forge kind (else 400) before anything else; the node must be one the caller may use for a project folder and must have announced `forge-clone:<limit>` (an older node is never sent the message: 409); then, before any row exists, the duplicate check (an in-memory claim on person, node and repository held until the row is written, then a read of the table: a double click is `409` however the two requests interleave, never a slot's `429`) and the limits that need no forge call (the person's own **clone** lookup slot, apart from the listing's one-per-person slot and waited for up to 3 s, one of the server's two forge slots, the person's forge rate); then one forge call, `GET` of that repository by name (exact, no paging: GitHub has no search by name), its answer read with the listing's rules; a name the forge answers differently (renamed, moved) is refused; the token goes to the node only when the forge says the repository is private.
**The node decides:** `[forge] hosts` (default `github.com`, `gitlab.com`), compared exactly as written, and `[forge] clone`; the host and name are checked again by the node's own rules (a host of a lower-case name or IPv4 with an optional port only if the entry has one; a name of 2 to 21 parts of `[A-Za-z0-9._-]`, none `.`, `..`, starting `-` or ending `.git`/`.atom`, at most 512 bytes), the login and token too (visible ASCII, no line break), all before git starts; the node builds `https://<host>/<full_name>.git` itself.
**The token's path:** never in argv, environment, a file or git config: written into a close-on-exec pipe whose reading end becomes that git's standard input in the child (never a descriptor the node unmarks, so a child another thread starts cannot inherit it); the only credential helper (a shell function in git's `-c`) answers `get` only for exactly that scheme, host and path (`credential.useHttpPath`), finds its git by the pipe's inode among at most six parents and reads the token from `/proc/<git>/fd/0` with the shell's `read`, printing it with `printf` (no program gets it as an argument); `http.followRedirects=false`; `http.proactiveAuth=basic` from git 2.46 (older: the 401 round trip).
A public repository has no helper and no stdin. git's error text is cut to 300 characters with the token and its Basic form removed.
**The command:** the hardened base (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, the environment cleared, `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=`, `protocol.allow=never`, `credential.helper=` reset, `core.sshCommand=false`) plus `protocol.https.allow=always` alone, `protocol.file/ext/ssh/git.allow=never`, `http.proxy=`, `transfer.bundleURI=false`, `fetch.bundleURI=`, `fetch.uriProtocols=` (no bundle or packfile URI from the server: another URL), `HOME`, `XDG_CONFIG_HOME` and `CURL_HOME` set to an empty 0700 folder the node makes in its staging folder for that clone and removes after (review of PR 163, M1: with `HOME` unset libcurl finds the node user's home through the password database and sends its `.netrc` credential, a `default` entry to every host; the environment is otherwise the hardened allow-list: `PATH`, `LANG`, `TMPDIR` and the node's own `GIT_*` values, so no inherited `GIT_*`, `SSL_*`, `CURL_*` or proxy variable reaches git), `core.hooksPath=/dev/null`, `core.fsmonitor=false`, `--no-recurse-submodules`, `submodule.recurse=false`, `transfer.fsckObjects`, `--template=`; no LFS filter exists, so pointers stay pointers.
**Bounds:** built in `<data>/projects-staging` and moved in with `renameat2(RENAME_NOREPLACE)` (a taken name gets new characters, as T77); `[limits] clone_timeout_s` (600) and `clone_max_mb` (2048; the staging folder walked every 500 ms while git runs and once after) end git's process group with SIGKILL, reap it and remove the build folder, the error naming the bound; a private clone whose git asked for a credential and got none (another process took it from the pipe) fails with a message saying so and telling the person to replace the token; an empty repository (no refs) gets `project.create`'s first empty commit on the branch the remote names as its default, and refs whose `HEAD` names no commit are refused; clones count against `projects_per_hour`; one at a time per node; the staging folder is emptied at start, so a restart mid-clone leaves no half folder; the master waits the node's limit plus 60 s, and a master that goes away leaves either the finished folder (named in the node's audit line) or nothing.
The project row records `source_host`/`source_name` once, at the create (no route changes it).
**Pending (X.27 step 3's screen, review of PR 163 L6):** the request answers `202` once the checks, the forge's answer and the send to the node passed (each refusal up to there is the request's own answer and leaves nothing); meanwhile a `project_clones` row (`cloning`, the project's future id, workspace, name, node, host, name as the forge spells it, starter) is all there is, and it is not a project (T77): every member of the workspace lists it under `pending` as cloning, with host and name but nothing of whose connection (`mine` only); the row and the forge call run in a task of their own, so a client that goes away leaves no row behind.
The same person, node and repository (any case) twice while one runs is `409` (checked and inserted in one store transaction, and a partial unique index behind the claim); a running clone counts against the workspace's project limit; the node's `projects_per_hour` and the forge limits are unchanged.
**Clones have a waiting budget of their own** among the requests waiting for nodes (8 on the server, 2 per person, counted apart from plain folder requests' 16 and 2): a clone waits up to the node's limit plus 60 s, and sharing the folder budget let eight people's clones refuse every plain "New project" on the server (review of PR 164, L3); past it a clone is `429`.
Ending: **the starter's right is checked again** when the node answers (review of PR 164, M2: the clone ran for up to ten minutes or more): the account still exists and is not disabled, still a member, still `settings` there, level and node still allowed, by the functions the request used; without it no project is written, and the row fails with a reason naming the folder the node made.
Then the node's folder makes the project (same id, folder, source) and deletes the row in one transaction; a refusal, a node that goes away or no answer in time keeps the row `failed` with the reason, shown to its starter only.
**The reason is cleaned by the master, not trusted to the node** (review of PR 164, L5/L6): control and Unicode format characters (bidirectional overrides and isolates, zero-width characters, the byte order mark, tag characters) are dropped, then the token, `login:token` and the base64 of that (padded, unpadded, URL-safe) are replaced by `[REDACTED]` (the master knows what it sent), then the text is cut to 300 characters; an orphaned folder's reason (a node path, at most 1,024 characters) cuts the free text to 300, the node's id to 64 and keeps the path whole: at most 1,500 characters in all.
A node whose **link closes** while it clones is not "not connected, start it": the node's clone task goes on, so the reason says the clone may still finish there and to open a folder that appears with Existing folder or remove it, and advises no retry (review of PR 164, M1).
A job that ends without writing the row's end (a panic, both store writes failing) fails the row with a plain reason from a drop guard, so none stays `cloning` until the next restart; shown to its starter only (others never see a failed row; nobody else can dismiss it: `DELETE /api/projects/{id}/clone` matches the starter), at most 10 kept per person (older ones go), counting against no limit; `projects_changed` to the workspace at the start and at the end.
At the master's start every `cloning` row becomes `failed` ("the server restarted…"): nothing waits for its node any more; the node still ends or finishes its git by its own bounds, and a folder it finished meanwhile is T77's residual (a folder no project keeps, logged by the master as an answer to a request it no longer has).
Tests: `crates/node/src/forge_clone_tests.rs` (23, a fake git server on 127.0.0.1 over `git http-backend` and a canary token: public and private clones both ways, every redirect case, `/proc` of a stalled clone, hostile requests with a marker git, a hostile repository and a hostile `HOME`, the size cap (after the fetch and while it runs), the time limit, a taken name, the restart sweep, the helper alone, the error scrub, the hourly cap, the node owner's `.netrc` mounted over the real home in a private mount namespace (never used) and in git's own `HOME` (used: the test's calibration), the environment's exact allow-list and empty home, an empty and a headless repository, a credential that never arrived, and the whole path through the runtime: capability, one at a time, a master that goes away, the token in no file of the data directory, no log at TRACE, no answer, no audit line), `master/tests/logs/forge_clone_http.rs` (20: with the pending state, the double request, each node refusal and the timeout, the restart, every project-id route refusing a pending project, and the review's: a link lost mid-clone, the starter removed, demoted or disabled mid-clone, the reason cleaned, cut and free of the token in every form, the orphaned folder's bound, the clone budget apart from folders, a listing in flight not refusing a clone, a refused request never showing a row) and `http::projects::clone` unit tests (the drop guard, the token's forms), `store/tests/projects.rs` `running_clones_count_against_the_limit_and_become_their_project`, `web/src/components/repopicker.test.tsx` (the screen: forge text inert and cut, the search's wait, cancel and 429), `protocol` `project_clone_carries_names_and_a_redacted_token`, `store/tests/projects.rs` `a_cloned_project_keeps_its_source`.
**Residual:** while a private clone runs, a process of the node's OS user that can read `/proc` (a host-mode chat; a sandbox that shares the host's `/proc`) can open `/proc/<git>/fd/0` and take the token before the helper does (same-user ptrace read access; nothing in an unprivileged process prevents it); a node the person chose receives the token of a private repository's connection, so a compromised node has it (and could ask for nothing more: it never gets it unasked); the token is in the master's and the node's memory, unwiped, while in use; the size cap can be overshot by what arrives in 500 ms; a node that crashes or is killed mid-clone leaves git running with no bounds until it ends on its own (the next start empties staging; same class as C.11; running git under the system's `timeout` would bound it without the node, not added); a public repository's forge sees the node's address;
GitHub Enterprise "internal" repositories count as private (the token is sent).
No fetch or pull, no workspace forge account, no LFS, no submodules (not in this step); the push is T101, through the same pipe and helper.
