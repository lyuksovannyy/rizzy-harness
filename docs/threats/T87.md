# T87

## Threat

**One message calls several agents by mention** (ADOPTION_PLAN X.37 step 1, README "Calling several agents"; `crates/core/src/mention.rs` (the rule, one pure function), `web/src/lib/mentionScan.ts` (its mirror, for drawing), `crates/master/src/peers.rs`, `crates/node/src/session_peers.rs`; the owner, 2026-11-19: "add ability to run multiple agent peers, where in order for one agent to contact other one it must start it's message with agent mention, like: \"@coder @writer, yo how it is goin?\" … when message contains mentions in middle of text, it wont trigger anybody but lets know @agent(s) where they needs to have attention"): text starts turns.
Abuse cases: (a) text nobody typed starts several turns, or a sub-agent-only agent is made to run as a chat agent by a mention (the API token, a routine, a webhook, a model, a node, an agent's own message); (b) a name that is not the chat's agent is called (another workspace's, a deleted one, a sub-agent-only one, a look-alike, another person's name, a file); (c) many turns from one message (a flood of mentions, a repeated name, a quadratic parse); (d) two turns at once or a turn out of order (one writer per session), a queued message lost or run twice; (e) Stop, a failed turn, a node or master restart leave agents unasked without saying so, or run an agent twice; (f) a called agent gets rights it did not have (connectors, memory, board, recall, the first agent's context); (g) an old node ignores the field, a hostile node writes a mention turn or a note the master never sent; (h) the command passes the link's size guard; (i) a mention turn breaks the replay.

## Mitigation

**The rule** (`mention::scan`, mirrored in TypeScript, one fixture `web/src/__fixtures__/mentions.json` read by both suites: 55 cases at this commit (the fixture is the count)): only the opening run and a last line of nothing but resolved mentions call; a mention is `@` at a token's start and `[a-z0-9-]+` ended by the end, a space, `,` or `:` (so `@coder.md`, `@src/main.rs`, `a@b.c` and `@Coder` are text); it counts only when the chat's own resolver knows it as an agent that may run as an agent (`Resolver::top_level`, the workspace's set, T79) or is the chat owner's own login (the person: no turn); nothing in a fenced block or inline code; one pass, no work that grows faster than the text (tests with 100,000 mentions and 100,000 backticks bound it at 5 s; they run in milliseconds), at most 5 agents kept so more than 4 is refused before anything is sent (b, c).
**Who may call** (`Master::prompt`; one test per term of the gate in `master/tests/it/peers_http.rs`, `every_term_of_the_gate_keeps_a_message_to_its_first_mention`, and the peer's spec builder refuses an untrusted chat by itself): only a message the chat's owner wrote signed in as themselves, in a chat that is not a sub-agent's, with no agent override, no answer to a card, no Retry, no parallel answers, not untrusted, not a callback or routine run; every other sender keeps today's single leading `@agent` (the first only: the API token's message "@coder @writer hi" answers as `@coder`, the rest is text; chosen over refusing so no existing routine breaks, and no extra turn can start from such text); for those other senders a leading `@agent` that runs only as a sub-agent is refused as it always was; in the owner's own message it is a tag (below) (a, b).
**Tags** (the owner, 2026-11-19: \"Any other (agents with sub-agent only perm can be tagged but wont trigger, good to mention which agent must run as sub agent)\"): an agent that runs only as a sub-agent resolves to `Who::Tag` in any position and is never in `called` (`trigger` is false for it; fixture cases and `master/tests/it/peers_http.rs`), it is part of the opening run and the last line (it neither ends the run nor makes the line text), does not count toward the 4, and the message holds at most 16 resolved mentions in all (`MAX_RESOLVED`, refused with a sentence before anything is sent); a leading sub-agent mention is no longer an error for the owner's own message (the API token's keeps the refusal); the answering agent's opening names only the tags it has among its own delegates after the node's bounds (`allowed_tags`; `session_peers.rs`, `node/tests/peers.rs`), built by one pure function, so a tag gives no right delegation did not already give and a replay is byte for byte; a name that is neither pickable nor a sub-agent, a removed one and another workspace's are text.
**The wire** (`session.prompt.peers`, only to a node that announced `peers`; at most 3 specs, the first agent stays `agent`): the master resolves every agent with the chat's resolver at send time and gives each peer's spec `remember`, `recall` and the board's tools denied and no connector tool, and no master context of their own (their turns are no send of the master's); an older node is refused the multi-agent message with a sentence and never sent the field; the node refuses more than 3 peers, an agent twice, a list with an answer to a card, parallel answers or in a sub-agent's chat, strips connector tools and bounds delegation by `[limits]` (the node decides); the command with four specs at the largest an agent may be (20,000 characters) is far under `MAX_PROMPT_JSON`, and the guard still refuses a command whose specs pass it, before sending (f, g, h).
**The order** (the node, `session_peers.rs`): the first agent's turn is the message's own; when a turn ends `completed`, `limit` or `error` the node claims the turn slot (the same `claim_turn`) and writes `turn_started` with `cause.mention` for the next agent; the specs are in memory only; a message sent in the instant between two turns is refused (the next agent comes first); a message sent while one runs follows X.5 (the running turn reads it at its next request; the next mention turn's first request is such a request; mention turns do not read queued messages at their start; the turn after the list reads what is left, as the agent that answered last); a message that itself calls several agents is refused while any turn runs (d).
**Stop** (`Session::cancel` sets a flag the chain reads before it claims a turn and again after, so a Stop between two turns is not lost) ends the turn and the rest and writes `peers_skipped` {stopped}; a node stop drops the list silently and the next start writes `peers_skipped` {restarted} from the log (`mention::unasked`: `user_message.triggers` less the agents that have a mention turn, once: a note ends the matter); a master restart changes nothing (the node keeps its list and the mirror replays); an agent that could not be started is named `unavailable` (e).
**Rights:** a mention turn is `granted = false` the moment its `turn_started` has any `cause` (`connectors::grant`, with a test that it takes no recorded send: the next owner message is still granted) and `OpenTurn::callback` refuses connectors, recall and the board in it (the message names the harness-started turn); `memory::file` files nothing from it; it is no callback for the budget (`callback_check`), counts as a person's turn for "finished, unread" and the background ends; its own checkpoint, cost line, approval mode and step limit apply (f).
**Replay:** `history_to_messages` rebuilds the opening at the turn's `turn_started` from the agent and cause alone (tested byte for byte in a later turn's request); the fold guard's table has the cause (`callback` or `mention`, exactly one, as serde reads it), `triggers` and `peers_skipped`, compared with serde's own schema (`browser_schema.rs` builds a kind's alternatives and takes a path found in some of them as optional); a mention turn for an agent the master never sent, or with no agent, is drawn and crashes nothing (g, i).
