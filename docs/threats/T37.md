# T37

## Threat

A program of the same user (an agent's shell command, foreground in an `auto` turn or a background command where they are on, with the network on) binds a loopback address of the master's port that the master accepts as its own origin but does not hold.
Browsers resolve `localhost` to `::1` first, so with the master on `127.0.0.1:<port>` only, a program on `[::1]:<port>` served `http://localhost:<port>`: the origin whose `localStorage` holds the login key (T2), with the cookie, and a perfect place for a fake login page (security review S2-1, `docs/security-review/2026-11-S2-1-loopback-origin.md`)

## Mitigation

**The master holds every loopback address it accepts** (`crates/cli/src/listen.rs`): a loopback bind (`127.0.0.1` or `::1`, or another `127.x`) also binds the other of `127.0.0.1:<port>` and `[::1]:<port>`; `0.0.0.0` also binds `[::1]:<port>` (never `[::]`, which would widen the exposure); `[::]` covers both when dual-stack (`IPV6_V6ONLY` read from the socket) and binds `127.0.0.1:<port>` when not.
A WireGuard or LAN bind accepts no loopback name and binds nothing beside.
One serve loop accepts from every listener in turn (one connection cap, one shutdown; `master/src/serve.rs`).
The binds come first in `serve`, before any runtime or node starts.
A second bind that fails with `EADDRINUSE` refuses the start, naming the address and that `http://localhost:<port>` would reach that program; nothing in the data directory is opened (no flag overrides it).
With port 0 the port is chosen again (16 tries). `EADDRNOTAVAIL`/`EAFNOSUPPORT` (no IPv6 here) start without it and drop `[::1]:<port>` from the allowed hosts; `localhost` stays (nothing can bind `::1` either).
Another process of the same user then cannot take the address: the master's sockets have `SO_REUSEADDR` (tokio; Linux ignores it against a listening socket) and not `SO_REUSEPORT`; a plain, `SO_REUSEADDR`, `SO_REUSEPORT` and both, and an IPv6-only or dual-stack `[::]` bind all get `EADDRINUSE`.
Tests: `cli/tests/loopback_origin.rs` (the abuse case and the refused start, on the real binary; skipped with a printed reason without `::1`), `cli/src/listen.rs` (the plan per bind, the error decision, the allowed hosts), `master/tests/it/server_limits.rs` `two_listeners_share_the_app_the_cap_and_the_shutdown`.
**Residual:** while the master is down any program of the user can hold its port, and a program that holds `[::1]:<port>` before a start now blocks that start (it is named); a container that publishes only `-p 127.0.0.1:7777:7777` leaves the host's `[::1]:7777` free (the README says to publish it too or to use `127.0.0.1` only); `--allowed-host` names are the owner's to hold; the UI certificate of `--tls` does not name `::1`.
