# T16

## Threat

Routines run without a human present, partly on external webhook data: injected text steers an agent or uses its web tools as a relay, a revoked user's routine keeps running, a webhook is abused or its sender locked out

## Mitigation

The owner's account, membership, `routines` permission and, for agentic routines, the grant and `agentic` permission are re-checked at every fire; a refusal pauses the routine.
Webhook data only fills the prompt, single pass, cleaned and capped, and marks the run untrusted: new chat, memory off, `web_fetch`/`web_search` and `remember` withheld, the routine's own agent, fixed title, an untrusted note; the flag sticks to the chat for every later turn (`routine_untrusted_chats`).
Agentic routines run in the mode their owner picks, `auto` by default (the owner's decision of 2026-11-14, in their words: "about routines default mode - auto, still when creating/editing an route - allows to select the mode"; T50): a scheduled routine in `auto` runs commands with nobody present, bounded by the node's `max_approval_mode`, the routine's own mode, the sandbox for sandbox chats, and the `ask` cap for a run with webhook data (`runner::run_mode`); parked approvals, delegates' included, are cancelled after 24 h.
Webhook secrets are 256-bit, header-only, stored as SHA-256, compared in constant time; throttles count failures only before authentication, and audit lines carry no content.
Caps per user, per workspace and per day.
