# T24

## Threat

An admin session (a careless admin, a stolen login, a second admin) uses the provider and model tests to read the server's own network: cloud metadata, a router, a database's HTTP port (SSRF, audit L3)

## Mitigation

`POST /api/admin/providers/test`, `/providers/models/test` (chat and embeddings) and every model listing (`refresh`, the daily refresh) go through `outbound::Outbound::provider_call` (`master/src/outbound.rs`): the URL must pass `url_allowed` (https, or plain http only to `localhost`/`127.0.0.1`/`[::1]` or a listed host; no userinfo), then the connection uses `web_fetch`'s public-only resolver, which checks the address actually connected to on every connection (DNS rebinding included); a private IP literal or `localhost` is refused before any connection.
Redirects stay on the same origin (`same_origin_redirects`), so a listed host cannot bounce the call inward.
Local model servers are allowed by name in `HARNESS_PLAIN_HTTP_HOSTS` (read at start), `localhost` included; the refusal names the variable and the value to add.
Tests: `master/tests/it/hardening_http.rs`, `outbound.rs`.
**Residual:** chat turns and memory embeddings use the saved provider URL without this check (it was checked by `url_allowed` when saved, but https to a private address passes that); the transcription client follows cross-origin redirects; a listed host may itself be a proxy to anywhere.
