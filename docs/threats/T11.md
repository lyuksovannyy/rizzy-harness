# T11

## Threat

A low-trust account gets a shell

## Mitigation

Agentic sessions run bash on a node, so they need a level (N.10a part 2, T39): the account's ceiling (default `none`; a server admin's counts as `host`) — the security boundary — and the member's level in the workspace (default `none`, never above the ceiling: the lower counts).
Both are checked at create and again before every command that makes a node work (`Master::send_command`), so lowering either stops further work above the new level; running agentic turns of affected users are cancelled, and the sweep runs again for a node's running sessions each time its link comes up (after its hello), so a turn on a node that was away during the revocation is cancelled on its return; a cancel the node's queue had no room for, or that it did not acknowledge, is tried up to 5 times over about 8 s (Gate 3 review P-3; `link_hardening.rs` `a_turn_that_lost_its_grant_while_its_node_was_away_is_cancelled_on_return`, `a_revocation_cancel_that_found_the_queue_full_is_retried`).
Residual: the turn keeps running while its node stays away, which is the node's own policy to bound.
Deny and cancel always stay possible: after losing either, on a diverged chat, and while the account must change its password (Gate 3 review P-7; `deny_always_http.rs`, `a_diverged_chat_refuses_an_allow_and_takes_a_deny`).
Chat sessions have no file or shell tools.
**The embedded node is for server admins** (`[nodes] local_node_users = "admins"`, the default): it runs as the server's own OS user beside its data directory; bash there is sandboxed (T4), but before Landlock ABI 9 the session bus or a Docker socket gets a command out of the sandbox (R2), so a shell there is still treated as admin-equivalent.
Other accounts get 403 ("use a remote node, or ask the server admin") at create and at every prompt, allowing approval and restore on a `local` chat, are not offered the node in `/api/nodes`, and new chats without a chosen node go to a remote one; agentic routines on `local` are refused at save and at every fire; demoting an admin cancels their running `local` turns.
The API token counts as admin. `"granted"` lets every account use it within its level, for installs where those accounts are trusted like admins.
**After a replay too** (R.4, fix review 2 R2-2): the sweep at a hello reads the mirror before the node's replay arrives, so a turn that started while the link was down, which only the replay shows as running, was missed.
When a replay of a session ends (the snapshot reached the node's head, or stopped), that session is swept again (`workspaces::cancel_revoked_session`); a cancel retried because the node's queue was full first checks that the turn still runs and its owner is still blocked, so a grant given back in the meantime keeps its turn.
Test: `master/tests/it/link_hardening.rs` `a_turn_known_only_from_the_replay_is_cancelled_when_it_lands`.
**The workspace `agentic` role is not a boundary yet** (review P-4, accepted until the build of `docs/nodes-credentials-environments.md`): a member demoted in a workspace can leave it, and the chat falls back to Personal, where the same node and folder are usable again at the account's ceiling (N.10a part 2; review L2-6: leaving unblocks what the team blocked, until a chat's node is checked against its workspace, N.1).
The signed-off nodes design closes it: a node serves named workspaces and a session's folder is derived per workspace, so leaving a workspace leaves its nodes and folders too.
Closed by that build, not before; until then the account's ceiling (N.10a part 2), not the workspace level, is what keeps a shell from an account.
