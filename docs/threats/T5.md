# T5

## Threat

Compromised master widens node permissions

## Mitigation

**Node-local policy (`node.toml`) is authoritative** and is not settable over the protocol or over HTTP (no endpoint writes it or installs software; graphify is allowed only by `graphify = true` in it, read at start): allowed workspace roots, max approval mode (`ask` default; master can request stricter, never looser), tool denylist.
The node logs every command it received in its own store.
**Delegation too** (Gate 3 review P-2): a `delegate` call goes through the node's approval path like any tool, before any child session exists. `denied_tools = ["delegate"]` refuses it with the policy's reason. `ask_all` asks for it.
Under `ask` it is not asked about: it changes nothing by itself, and the child's own calls are gated. `[limits] max_subagents` (default 4) and `max_delegation_depth` (default 1) bound the master's agent spec at every level: the spec may ask for fewer, never more (`LimitsPolicy::bound_delegation`, applied to every prompt).
Tests: `node/tests/runtime.rs` `a_node_that_denies_delegate_refuses_it_before_any_child_exists` (the review's proof inverted), `ask_all_asks_before_a_delegation_and_ask_does_not`, `node_limits_clamp_the_masters_delegation_caps_and_depth`.
The per-turn token cap of sub-agents still comes from the master alone.
What the master forwards at create is checked there first (R.4, review N-5): a `model` the chat's workspace does not list is refused before anything reaches a node ("unknown model"), and `approval_mode` is a closed enum that the node clamps again; a command whose caller goes away mid-wait no longer leaves its pending-ack entry behind (a guard removes it however `send_command` ends; `master/tests/it/link_hardening.rs` `an_abandoned_command_leaves_no_ack_and_an_unknown_model_is_refused`).
**The node's own record of the master's commands** (its `audit` table): a lane command's line is written before it acts; an inline one's (cancel, approval answer, `stop_background`) after it acts and is acked, through one audit writer (`node/src/audit.rs`, A.21, review A21-1), so rows no longer follow command order; each row's `ts_ms` is taken when the line is queued, which keeps the order the commands arrived in.
A line the writer cannot keep or write is counted and the count recorded as one `audit.not_recorded` line; a clean stop waits for both within its flush bound and says at error level what it left (re-check D-2).
A crash loses what was queued and the count not yet written: at most 1,024 lines and one count, usually a few milliseconds' worth.
The cross-check is the session's log, on the node and in the master's mirror: the events the commands caused (a turn started, an approval resolved, a turn ended cancelled); the master keeps no audit line per command it sends.
