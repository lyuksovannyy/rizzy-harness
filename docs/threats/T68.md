# T68

## Threat

**Following up a sub-agent** (ADOPTION_PLAN X.22; `delegate` with `session`): a parent sends a sub-agent it already ran its next message, and the child continues its own conversation. (1) The model names a child that is not its own (another chat's, a grandchild, a sibling's, an unknown or deleted id, a forged string) to reach its history or its folder. (2) A child gains by being continued what a new child would not get: a tool, a wider mode, a writable folder, another agent's tools, a way around the depth limit or the caps. (3) Two runs of one child at once, or a follow-up while it works. (4) A continued writer works on stale files or its read-first table claims reads of files that changed. (5) A child asked over and over without bound.

## Mitigation

**The node decides from its own log, never from the id the model wrote** (`session.rs` `run_continue`): the child's `session_created.parent_session` is the calling session, the caller's own log holds a finished `delegate` call (`tool_call_started` with tool `delegate`) whose result begins with `session: <id>`, and the child was started as the agent the call names; unknown, deleted, foreign and the caller's own id get one sentence that says nothing about other sessions.
The agent must be one of the caller's delegates as the node bounds them now (`bound_delegation`), so depth and the per-turn caps hold as for a new child (a child at the depth limit has no `delegate` at all), and the call is counted against `max_subagents` and the token budget.
It runs with what a new child of that agent gets now: its tools from the current definition clamped by the node; the parent's mode read at every call as a ceiling (`current_mode`, T50), so a child made in Auto asks once the chat is in Ask; its execution mode as recorded (always its parent's, N.10a).
It never gains a writable folder: one that only read and whose agent can now change files, or the reverse, is refused; a writer gets a fresh node-owned copy of the parent's folder as it is now at its own path (`<data>/sessions/<id>/files`, re-pinned before the turn) and is merged back three ways as before; a reader works in the parent's folder.
One turn at a time: the loop refuses a second follow-up to the same id in one step, and the node's turn slot refuses any other (a differently spelled id included).
Its opening carries a fixed harness line (`subagent::FOLLOW_UP_READS`, `follow_up_writes`) recorded in `turn_started` so requests rebuild byte for byte; the read-first table (T45) holds as for any turn: a `write` over a file that changed since the child read it is refused until it reads it again; an `edit` is refused where the lines it edits changed (the table keeps what the child was shown), and otherwise runs with a note that the file changed; the harness line also says whether its earlier changes landed in full, in part (`NotApplied::Partial`) or not at all.
At most `MAX_CHILD_RUNS` (8) runs per child.
The child's answer, `finish`, sources and end text are read from that turn's events only.
Plan mode (T67): with the chat in plan mode a child that changes files is not continued (refused by the node, before its folder is touched); a child made in plan mode stays in it for life (its recorded mode is its floor) and is never given a writable folder by a follow-up, whatever its agent could; a reader continued in plan mode runs in plan mode; entering plan mode denies a continued child's waiting card like any sub-agent's.
A writer whose node restarted between runs is continued like any other (its folder was removed after its last run anyway).
Tests: `node/tests/continue_child.rs` (same child and its conversation; unknown, malformed, own and foreign ids; deleted child; another agent; the same child twice in one step and spelled differently; caps; the run limit; a writer's fresh copy and merge; an unapplied child's copy; the read-first table, a changed and an unchanged region; Ask; depth; rebuild of the child's request, also after a summary inside the child between runs; usage counted once; nothing of a first copy survives; an unremovable copy fails closed; a `session` that is not an id is refused; a child of an undone turn; plan mode: a writer not continued, a child made in plan mode stays in it, a reader continued in plan mode, a waiting card denied on entering it), `agent-native` `delegate_offers_follow_ups`, `agents` Team Lead prompt test, `web` `sideItems.test.ts`, the shared fold fixture.
