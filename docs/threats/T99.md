# T99

## Threat

**A person previews a Word or Excel file in the page** (ADOPTION_PLAN X.58, README "Looking at a file").
The file is hostile (the agent's text, or a file someone else wrote and the owner attached): script-looking text, a `javascript:` hyperlink, direction and control characters, a formula such as `=HYPERLINK(...)`, a cell that starts with `=cmd|`, a zip bomb, a document of 100,000 paragraphs or a sheet of a million cells.
The route gives the page the contents of a chat's file, so the questions are who can ask, what the page does with the text, and what a large or slow file costs the server.

## Mitigation

**Who.**
`GET /api/sessions/{id}/files/{file_id}/preview` takes the normal login (a cookie and the page's key, not a link: this is JSON read by script, and a page of another origin cannot read it) and the checks of the download: the chat is opened through `visible_session` (another person, an admin too, gets the 404 a chat that does not exist gets, T10), it is a plain top-level chat that is not temporary, the file is a row of that chat's own `session_files` that the chat's log names (`logged`), and the blob is the chat owner's.
The server's API token reads any chat, as it can download from it (T10), and holds its own helper place (`api-token`), as for attachments.
A file of another chat of the same owner, a held row, a coding chat, a temporary chat and a sub-agent's chat are the same 404 (`crates/master/tests/it/doc_preview_http.rs::nobody_else_previews_and_a_file_id_is_only_its_own_chats`, `::a_planted_row_a_folder_chat_an_incognito_chat_and_a_sub_agent_are_not_previewed`, `::the_owner_previews_a_made_file_and_an_attached_one`, `::the_api_token_previews_as_it_downloads`; the blob-owner check is proved by a planted row with the blob's real size, so that nothing else refuses it).
A made file and an attached .docx or .xlsx go through the same row.
**How the file is read.**
Only by the confined `doc-edit` helper (T98), through one more request that returns data (`Request::Preview`, `deny_unknown_fields`), never in the master's process; the master sends the id of one of the chat's own files and an optional sheet number.
A sheet is asked for by its place among the visible sheets (`?sheet=<n>`, an integer), never by name: a name is the file's text, cleaned for the page, and one with a double space, a zero-width character or a twin could not be sent back (`tests_preview.rs::a_sheet_is_picked_by_its_place_so_any_name_can_be_opened`).
A name that is not `.docx`, `.docm`, `.xlsx` or `.xlsm` is a 415 without a helper run.
The helper answers with a reason (`Why`, decided in the engine from the bytes and from the reader's own limit refusals, not from message text): not a Word or Excel file (not a zip, or a zip with neither part; 415), protected with a password (an OLE container, `D0 CF 11 E0`; 422), too large (a part over 8 MiB once unpacked, more than 200,000 paragraphs, 300,000 rows, 4,000,000 elements or 4,000 parts; 422 "download it": these are refused, not cut), damaged or refused (cut short, protected or signed, a `DOCTYPE`, encrypted entries; 422), no sheet at that place (400).
An empty file is a 422 "empty"; a file over 10 MB a 413; a helper that cannot confine itself or a server without the reader a 503; an answer the master cannot read or over 512 KB a 502; the master reads at most 640 KB of the helper's output for a preview, so more is a failed helper (422).
The helper's own words are never forwarded, since they may hold a name from the file, and nothing of the file (its name, its text) is written to a log (`::each_reason_has_its_own_sentence`, `::what_is_not_a_document_is_415_and_a_failing_helper_does_not_leak`, `::a_reply_past_the_limit_is_not_forwarded`, `::the_helper_may_answer_only_a_preview_sized_reply`; `crates/docs/src/edit/tests_preview.rs::what_is_not_a_document_says_which_kind_of_not`, `::a_file_past_a_limit_is_too_large_not_damaged`).
**One at a time.**
The account's one helper slot (`PdfReader::account_slot`, as for attachments and the editing tools) holds a second preview of the same account for at most the queue bound and then answers 503, so many previews at once from one account cannot fill the server's two slots; another account is not held up; the blob is read only after the slot is held (`::one_account_runs_one_preview_at_a_time`).
The hidden columns of a sheet are merged into sorted ranges once and searched, so tens of thousands of `<col hidden>` entries cost no more per cell (`tests_preview.rs::tens_of_thousands_of_hidden_column_ranges_are_merged_and_answered_right`; `doc_view` shares the function).
The route is not counted against the agent's 60 calls a turn, which belong to the model's tools.
**A file of a coding chat's folder (X.59).**
`GET /api/sessions/{id}/folder-preview?path=&sheet=` gives the same answer and the same sentences, but the master runs and reads nothing: it sends the owning node one `session.doc_preview` (the path as text of at most 1,024 bytes, a sheet place) and hands the page what the node's one `session.doc_preview_result` carries, from that node only (`crates/master/src/folder_preview.rs`).
Who: the chat is opened through `visible_session` (another person, an admin too, gets the 404 of a chat that does not exist, and the node is never asked) and the agentic grant that reaching the folder needs (`http/files.rs`); a chat without a folder and a temporary chat are the same 404; an empty path or one over 1,024 bytes is a 404 and asks nothing (`crates/master/tests/it/folder_preview_http.rs::nobody_else_previews_not_even_an_admin_and_the_node_is_never_asked`, `::a_plain_chat_and_a_bad_path_are_404_and_ask_nothing`, `::a_temporary_coding_chat_is_404_and_asks_nothing`; the agentic grant: `::an_owner_who_lost_the_level_is_refused_and_the_node_is_never_asked`).
The node decides: it resolves the path as the `read` tool does (the pinned folder, a sub-agent's own, links followed and judged, protected places), never outside the folder even where node.toml lets the agent read outside, never inside `.git`, only a regular file opened without blocking, at most 10 MB, and not at all where node.toml denies `read`.
Every way of not reaching a file (outside, missing, a directory, a FIFO or device, a link out, `.git`, a protected place, a control character in the path, an unknown chat, a node without a folder) is the one answer `not_found`, so nothing about the target leaks (`crates/tools/src/folder_preview.rs::tests::every_way_out_is_the_one_not_found`, `::the_outside_mode_of_the_node_does_not_widen_a_preview`, `::a_directory_a_fifo_and_a_device_do_not_hang`; `crates/node/tests/folder_preview.rs`, over the link, which also asserts the log has the same length after: the request appends no event).
The helper is the same confined `doc-edit` (T98); its words are never forwarded, only a word of ours (`::a_failing_helper_is_a_word_and_leaks_nothing`; the real helper on a hostile document in `crates/cli/tests/doc_edit.rs::a_folder_file_is_previewed_through_the_node_helper_and_a_hostile_one_is_refused`).
What the node sends is read once by the master into the typed `Preview`: an answer that is no preview, or over 512 KB, is a 502 and is not forwarded (`::each_refusal_has_the_sentence_of_the_other_route`).
One at a time: one waiting request per account on the master (`::one_account_previews_one_file_at_a_time`, and `folder_preview::tests::the_places_are_bounded_per_account_and_in_all` for the bound on all accounts together) and one on the node (`crates/node/tests/folder_preview_busy.rs`), so a person's previews take at most one of the helper's two places and the agent's own `doc_view` keeps the other; a second is told to try again.
A request the page gives up frees the account's place at once (`::a_request_the_page_gave_up_frees_the_accounts_place`), and an answer from a node that was not asked is ignored (`::another_nodes_answer_to_a_request_is_ignored`).
Known and plain: the node's one place is shared by ALL accounts on that node, and the node keeps reading, up to about 30 s, after a browser has gone away, so on a shared node one account that retries in a loop can keep the others at "busy" for as long as it does; the agent's own helper place is unaffected.
There is no per-account limit on the node; the master's one place per account only stops one account from queueing many at once.
An older node is asked nothing (409 "this chat's node cannot preview files; update the node"); a node that is away is the sentence the `@` completion gives (`::an_old_node_and_an_away_node_get_a_sentence_not_a_hang`).
The folder file's too-large sentences say "open it in Word or Excel", since the panel has no download for it (`::each_refusal_has_the_sentence_of_the_other_route`; the other route keeps "download it": `doc_preview_http.rs::each_reason_has_its_own_sentence`).
The path is in the query: it is not a secret, and no log line holds a query (the request log and the timeout log write the path of the URL only; the node's audit line holds the session id only).
The answer is `no-store`.
Residual: a directory inside the folder that is swapped for a link between the path check and the open is followed, because the open is by path (the existing gap of the `read` tool's `open_regular`, not made here and not fixed here); for the preview only a file that parses as a Word or Excel document is shown, and only to the folder's owner.
Accepted: the page can ask the node to resolve any path of the folder it can read (it is the owner's own folder, and what the node would show the owner's agent); the preview has no download.
**A text file of a coding chat's folder (X.63).**
`GET /api/sessions/{id}/folder-file?path=` has the checks and the read rules of the folder preview, shared in code (`crates/tools/src/folder_preview.rs::locate`), so the two cannot drift: the owner only through `visible_session` (another member, a server admin and a workspace admin get the 404 of a chat that does not exist and the node is never asked: `crates/master/tests/it/folder_file_http.rs::nobody_else_reads_not_even_an_admin_and_the_node_is_never_asked`, `::a_workspace_admin_is_not_the_owner`), the agentic grant (`::an_owner_who_lost_the_level_is_refused_and_the_node_is_never_asked`), a plain chat, a temporary chat and a path that is empty or over 1,024 bytes are a 404 that asks nothing (`::a_plain_chat_a_temporary_chat_and_a_bad_path_are_404_and_ask_nothing`).
The node: every way of not reaching the path (outside, `..`, absolute, a link out, `.git`, a protected place, a directory, a FIFO or device, a control character, too long, an unknown chat, a node without a folder) is the one `not_found`, also where node.toml lets the agent read outside (`crates/tools/src/folder_file.rs::tests::every_way_out_is_the_one_not_found`, `::the_outside_mode_of_the_node_does_not_widen_a_view`, `::a_fifo_and_a_device_do_not_hang`; over the link `crates/node/tests/folder_file.rs::paths_that_leave_the_folder_or_are_not_files_are_one_answer`, which also asserts the request appends no event).
A node that denies `read` answers `denied` and reads nothing (`::binary_is_said_and_denied_read_shows_nothing`).
The read is bounded whatever the file: the first 8,000 bytes decide "binary", at most 256 KiB plus a 4 KiB margin are read, a 5 GB sparse file is answered in well under a second (`::a_huge_file_is_read_in_part_and_fast`).
Secrets: the text passes the node's scrubber, the margin included so a key that straddles the cut is redacted whole, before it is cut; the test fails with the scrubber removed (`::a_secret_is_scrubbed_also_across_the_cut`; over the link `::a_file_is_read_scrubbed_and_appends_no_event`).
Residual: a secret split by an escape sequence or other characters inside it is not matched by the scrubber (as in a `read` result), and a secret longer than the 4 KiB margin could show in part at the cut.
Content: the page draws the text as React text only after `showHidden`, so markup, an escape sequence and a direction override are inert and visible (`web/src/components/folderfile.test.tsx`; in a real browser `web/e2e/folder-file.cjs`: a `<script>` and `<img onerror>` file ran nothing and made no element, and a 1 MB single line is cut at 256 KiB, scrolls and breaks no layout).
A node's answer of more than 256 KiB of text, or of a word this master does not know, is a 502 and is not forwarded (`::each_refusal_has_its_sentence`); the places are those of the preview, one waiting request per account, shared with it, and an answer from another node or of another kind is ignored (`::one_account_reads_one_file_at_a_time_and_a_forged_answer_is_ignored`, `::a_request_the_page_gave_up_frees_the_accounts_place`).
The controls that open it are made only from fields that are paths (a changed file's path, a card's `path` input, a made file's path), never from text the model wrote in prose.
Accepted: as for the preview, the page can ask the node for any file of the owner's own folder that the node would show the owner's agent.
**What it returns, and what bounds it.**
Structure and strings, no HTML: a document is blocks (`h` level 1 to 6 by the style's name, `p`, `li`, `t` rows of cell strings) of runs with `b`, `i` and `s` from the run's own properties (direct formatting only; a character style such as Strong is not followed); a workbook is the visible sheets' names and one sheet's rows of cells with an address, the shown value or, for a formula, the formula as `doc_view` prints it.
It is read by the code of `doc_view`, so hidden text, tracked deletions, objects, hidden rows, columns and sheets are left out the same way; a text box's text is not shown, and an object is `[obj]`.
Every string is cleaned in the helper: invisible, zero-width and direction characters dropped, controls read as a space.
The reply is bounded by constants in `crates/docs/src/limits.rs` (`MAX_PREVIEW_*`): 2,000 blocks, 5,000 table cells in all, 500 rows, 50 columns or cells per row, 5,000 characters per paragraph, 500 per cell, 100 sheet names and 200,000 bytes of JSON counted as it is built (strings as JSON writes them, so quotes are counted twice); when anything is cut `more` is set and nothing fails; each limit is tested at its edge and one past (`crates/docs/src/edit/tests_preview.rs`).
The same real helper is run in `crates/cli/tests/doc_edit.rs::the_helper_previews_a_document_a_workbook_and_nothing_else`.
**What the page does with it.**
Every string is drawn as a React text node (`web/src/components/DocPreview.tsx`): no `dangerouslySetInnerHTML`, no image, no link made from the file (the only link on the panel is the download, a link of the chat's own file); hidden and direction characters that reach the page are shown as codes; a formula is text in a cell, never a link; a cell address that is not a letter and a number is dropped; a heading level is clamped; the file's name is text (`web/src/components/docpreview.test.tsx::nothing_from_the_file_becomes_html_an_image_a_script_or_a_link`).
The answer is `no-store` like every API answer.
Known and accepted:
- The preview is not the page: fonts, colours, pictures, charts, comments, headers, footnotes and page breaks are not shown, and a document whose text is in text boxes shows `[obj]` where the box is.
- A sheet shows the values the file stores as the view does: a formula has no value here, so a person sees the formula and not the number Excel would show.
- The preview and the download read the same stored copy; nothing is written or changed.
- On a kernel without Landlock (or before ABI 4) the helper refuses and the panel says so.
