# T99

## Threat

**A person previews a Word or Excel file in the page** (ADOPTION_PLAN X.58, README "Looking at a file").
The file is hostile (the agent's text, or a file someone else wrote and the owner attached): script-looking text, a `javascript:` hyperlink, direction and control characters, a formula such as `=HYPERLINK(...)`, a cell that starts with `=cmd|`, a zip bomb, a document of 100,000 paragraphs or a sheet of a million cells.
The route gives the page the contents of a chat's file, so the questions are who can ask, what the page does with the text, and what a large or slow file costs the server.

## Mitigation

**Who.**
`GET /api/sessions/{id}/files/{file_id}/preview` takes the normal login (a cookie and the page's key, not a link: this is JSON read by script, and a page of another origin cannot read it) and the checks of the download: the chat is opened through `visible_session` (another person, an admin too, gets the 404 a chat that does not exist gets, T10), it is a plain top-level chat that is not temporary, the file is a row of that chat's own `session_files` that the chat's log names (`logged`), and the blob is the chat owner's.
The server's API token reads any chat, as it can download from it (T10), and holds its own helper place (`api-token`), as for attachments.
A file of another chat of the same owner, a held row, a coding chat, a temporary chat and a sub-agent's chat are the same 404 (`crates/master/tests/it/doc_preview_http.rs::nobody_else_previews_and_a_file_id_is_only_its_own_chats`, `::a_planted_row_a_folder_chat_an_incognito_chat_and_a_sub_agent_are_not_previewed`, `::the_owner_previews_a_made_file_and_an_attached_one`, `::the_api_token_previews_as_it_downloads`; the blob-owner check is proved by a planted row with the blob's real size, so that nothing else refuses it).
A made file and an attached .docx or .xlsx go through the same row.
**How the file is read.**
Only by the confined `doc-edit` helper (T98), through one more request that returns data (`Request::Preview`, `deny_unknown_fields`), never in the master's process; the master sends the id of one of the chat's own files and an optional sheet number.
A sheet is asked for by its place among the visible sheets (`?sheet=<n>`, an integer), never by name: a name is the file's text, cleaned for the page, and one with a double space, a zero-width character or a twin could not be sent back (`tests_preview.rs::a_sheet_is_picked_by_its_place_so_any_name_can_be_opened`).
A name that is not `.docx`, `.docm`, `.xlsx` or `.xlsm` is a 415 without a helper run.
The helper answers with a reason (`Why`, decided in the engine from the bytes and from the reader's own limit refusals, not from message text): not a Word or Excel file (not a zip, or a zip with neither part; 415), protected with a password (an OLE container, `D0 CF 11 E0`; 422), too large (a part over 8 MiB once unpacked, more than 200,000 paragraphs, 300,000 rows, 4,000,000 elements or 4,000 parts; 422 "download it": these are refused, not cut), damaged or refused (cut short, protected or signed, a `DOCTYPE`, encrypted entries; 422), no sheet at that place (400).
An empty file is a 422 "empty"; a file over 10 MB a 413; a helper that cannot confine itself or a server without the reader a 503; an answer the master cannot read or over 512 KB a 502; the master reads at most 640 KB of the helper's output for a preview, so more is a failed helper (422).
The helper's own words are never forwarded, since they may hold a name from the file, and nothing of the file (its name, its text) is written to a log (`::each_reason_has_its_own_sentence`, `::what_is_not_a_document_is_415_and_a_failing_helper_does_not_leak`, `::a_reply_past_the_limit_is_not_forwarded`, `::the_helper_may_answer_only_a_preview_sized_reply`; `crates/docs/src/edit/tests_preview.rs::what_is_not_a_document_says_which_kind_of_not`, `::a_file_past_a_limit_is_too_large_not_damaged`).
**One at a time.**
The account's one helper slot (`PdfReader::account_slot`, as for attachments and the editing tools) holds a second preview of the same account for at most the queue bound and then answers 503, so many previews at once from one account cannot fill the server's two slots; another account is not held up; the blob is read only after the slot is held (`::one_account_runs_one_preview_at_a_time`).
The hidden columns of a sheet are merged into sorted ranges once and searched, so tens of thousands of `<col hidden>` entries cost no more per cell (`tests_preview.rs::tens_of_thousands_of_hidden_column_ranges_are_merged_and_answered_right`; `doc_view` shares the function).
The route is not counted against the agent's 60 calls a turn, which belong to the model's tools.
**What it returns, and what bounds it.**
Structure and strings, no HTML: a document is blocks (`h` level 1 to 6 by the style's name, `p`, `li`, `t` rows of cell strings) of runs with `b`, `i` and `s` from the run's own properties (direct formatting only; a character style such as Strong is not followed); a workbook is the visible sheets' names and one sheet's rows of cells with an address, the shown value or, for a formula, the formula as `doc_view` prints it.
It is read by the code of `doc_view`, so hidden text, tracked deletions, objects, hidden rows, columns and sheets are left out the same way; a text box's text is not shown, and an object is `[obj]`.
Every string is cleaned in the helper: invisible, zero-width and direction characters dropped, controls read as a space.
The reply is bounded by constants in `crates/docs/src/limits.rs` (`MAX_PREVIEW_*`): 2,000 blocks, 5,000 table cells in all, 500 rows, 50 columns or cells per row, 5,000 characters per paragraph, 500 per cell, 100 sheet names and 200,000 bytes of JSON counted as it is built (strings as JSON writes them, so quotes are counted twice); when anything is cut `more` is set and nothing fails; each limit is tested at its edge and one past (`crates/docs/src/edit/tests_preview.rs`).
The same real helper is run in `crates/cli/tests/doc_edit.rs::the_helper_previews_a_document_a_workbook_and_nothing_else`.
**What the page does with it.**
Every string is drawn as a React text node (`web/src/components/DocPreview.tsx`): no `dangerouslySetInnerHTML`, no image, no link made from the file (the only link on the panel is the download, a link of the chat's own file); hidden and direction characters that reach the page are shown as codes; a formula is text in a cell, never a link; a cell address that is not a letter and a number is dropped; a heading level is clamped; the file's name is text (`web/src/components/docpreview.test.tsx::nothing_from_the_file_becomes_html_an_image_a_script_or_a_link`).
The answer is `no-store` like every API answer.
Known and accepted:
- The preview is not the page: fonts, colours, pictures, charts, comments, headers, footnotes and page breaks are not shown, and a document whose text is in text boxes shows `[obj]` where the box is.
- A sheet shows the values the file stores as the view does: a formula has no value here, so a person sees the formula and not the number Excel would show.
- The preview and the download read the same stored copy; nothing is written or changed.
- A file in a coding chat's folder is not previewed (the node owns it; its own request over the link).
- On a kernel without Landlock (or before ABI 4) the helper refuses and the panel says so.
