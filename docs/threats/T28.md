# T28

## Threat

The node's store cannot append (full disk, I/O error, a corrupted or locked database, perhaps brought about on purpose by a command that fills the disk), and the agent keeps acting with nothing in the log: a tool runs, an approval is acted on, the model is called, none of it auditable or visible to the user (final review A6, A7)

## Mitigation

**A failed append ends the turn** (§2, "A failed append ends the turn"): `TurnHost::emit` is fallible; the native loop (`agent-native`, `Logged`) stops at the first failure, cancels the turn's token (running tool and parallel delegations stop within the grace period) and fails every later append untried; the node's session denies an approval whose request or answer was not written, skips the after-turn checkpoint, tries the closing `error` and `turn_ended` once each, frees the turn slot and, if the end was not written, closes that turn before the next prompt.
A prompt whose `turn_started` or message cannot be written is refused with the store's reason, so the sender sees it.
One `tracing::error!` per turn, with the store's error only.
Tests: `agent-native` (`a_tool_does_not_run_when_its_start_cannot_be_logged`, `no_model_request_after_a_result_cannot_be_logged`, `a_failed_append_cancels_the_parallel_delegations`), `node/tests/runtime.rs` (`a_tool_does_not_run_when_its_event_cannot_be_written`, a real SQLite store broken by a trigger).
Also: an approval whose answer was not written is denied at the turn's end, so the log never leaves it pending; a sub-agent's worktree is not merged after its own or its parent's log failed, and the parent's result says the sub-agent stopped because its log could not be written (each session's log gates its own effects, §2); a staged file whose `artifact_staged` cannot be written is released and, during a turn, ends it; a `before` checkpoint ref whose event failed is deleted.
More tests in `node/tests/runtime.rs` (`an_approval_whose_answer_was_not_written_is_closed_with_the_turn`, `a_sub_agent_whose_log_failed_changes_nothing_in_the_folder`, `a_failed_append_kills_the_running_command`, `an_unclosed_turn_is_closed_once_by_a_restart`) and `node/tests/artifacts.rs`.
**Residual:** a tool that was already running when a later append failed (one of its output deltas) has had its effect, and its result is not recorded; a turn whose end could not be written shows as running in the UI until the next prompt or a node restart closes it, and for a sub-agent's session (which gets no further prompt) until a node restart; the mirror and the UI learn of a mid-turn failure only when the store works again (no other channel, no new protocol message).
Undo/restore is under the rule since A.9 (T33).
