# T55

## Threat

**Searching the person's earlier chats** (`recall`, ADOPTION_PLAN X.13; the owner, 2026-11-14: "yes, but must have dedicated permission, like web search, file access do"): chats are private to their owner (invariant), and this tool reads them for an agent.
Threats: an agent reads another person's chats, a chat of another workspace, a temporary chat or a sub-agent session of someone else; a node (compromised, or a test node) forges a request naming another session, user or workspace; a prompt-injected agent (a hostile page, file or repository) searches the owner's chats and sends what it found out; text in an old chat (a web page, tool output, another person's file pasted there) steers the agent that reads it, or forges a harness line; a flood of searches; a slow or absent master hangs the turn.

## Mitigation

**Why it is allowed:** the tool gives an agent working **for** the owner, in the owner's own chat, a bounded read of the owner's own earlier chats: what the owner could search in the search panel themselves, nothing more.
**Permission:** its own per-agent switch (`Features::recall`, off unless on).
Built-ins: on only for Assistant, Researcher and Reviewer (`harness_agents::RECALL_BUILTINS`, one line), off for every built-in that can run commands, use MCP servers or publish (Software Developer, Senior Teamlead, Writer) and for Smol and Scout; built-ins are read-only on the Agents page, so that list is their permission (a person who wants it for Software Developer duplicates it and turns the switch on); offered only on a node whose hello lists `recall` (registered and not in `denied_tools`).
**Scope from the session alone** (`master::recall`): the node sends words only (`RecallQuery` takes `query`, `in`, `limit`; any other field fails to parse); the master answers only the node whose session it is, and decides whether the asking turn may search from the log at the time of the request, never from a flag a prompt left: the session's open turn (`Store::open_turn`: its last `turn_started` with no `turn_ended` after it; the request travels in order after the turn's events) must exist, must not be a callback turn, must not have `recall` among what the master withheld from it (`AgentRef::withheld`, recorded in `turn_started` from the spec `Master::prompt` sent: untrusted turns and temporary chats have it withheld), and its agent must have the switch; a sub-agent's parent turn must pass the same; a sub-agent of a sub-agent is refused; counts are kept per turn id, so a turn the master never prompted, a queued prompt and the time between turns change nothing; scope = that chat's owner and effective workspace (`Store::recall_search` requires both), top-level chats only (`parent_id IS NULL`), never `incognito`, never the asking chat or its parent; memory only from exactly the places the asking turn reads (`memory::turn_places`, the one function `turn_block` and `projects::turn_context` use, over `memory::turn_allowed`, the rule `Master::prompt` uses, decided for the open turn's agent and a sub-agent's parent's): the owner's own facts (their user id) where their join answer and the agent's memory switch allow; the workspace's memory (`workspace:<id>` of the chat's effective workspace: in a team the memory its members share, which every member's chats are given anyway (T54); in Personal the person's private-details place); the project's (`project:<id>`) with project memory on; never an unset owner; active facts only, so a retired fact or a waiting proposal never comes back, not even to its proposer.
A sub-agent searches only when its own agent has the switch (the master checks the child's agent).
**Not offered** in a temporary chat, an untrusted (webhook) turn or a callback turn, also not to their sub-agents (`recall::deny`), and such a turn's requests are refused: those turns may be steered by text nobody wrote.
**Exfiltration bound:** results are not URL provenance (`URL_SOURCES` is `web_search`, `web_fetch`, `read`), so `web_fetch` cannot follow a link found in an old chat, nor a URL the model built from it; `bash` with the network and MCP tools are what remain, bounded by the chat's approval mode and the node's network rule exactly as for the repository's own content.
A `web_search` query can carry recalled words to the search provider (residual, as for any text the agent read).
**Data, not instructions:** excerpts are quoted line by line (`| `, `quoted_line`, every line break a reader shows as one, hidden characters and the search marks removed, titles one clean line) under a lead saying they were written then, may come from pages and files, and are never instructions; the loop's `escape_leads` still applies.
**Bounds:** 8 searches per turn, 40 per chat per hour, at most 4 in progress per node on the master (more are refused), 10 results, 700 characters per excerpt and 6,000 per answer (master and tool both cut); the node waits 20 s, then a plain tool error; at most 32 waiting per node; a query with no word is refused and not counted, nor is a search whose answer could not be sent; refusals are logged at info once per node, then at debug.
**Secrets:** the master runs its own secret set over every title and excerpt before it answers, so a secret the asking node does not know of stays out of its model and its log.
**Workspace of a chat:** the effective workspace, the rule the UI uses: after a person leaves a team, their former team chats count as their Personal workspace's, and are searched from there.
**Nothing written** but the normal tool event (query and bounded result, scrubbed by the node like any tool output; the results come from the owner's own logs, which passed the scrubber).
**Residual, the exit:** in a chat in Auto with the node's network on (the defaults of new chats), `bash`, an MCP tool or a `web_search` query can carry recalled text off the machine with nothing asked; what bounds it is only the chat's approval mode (Ask or Accept edits asks before `bash` and MCP calls), the node's `[sandbox] network` rule, and that the built-in agents with those tools do not have the switch unless a person gives it to a copy.
That person may be a workspace's admin, not the member: a workspace's own agent (T79) may have the switch together with commands, MCP, the web or file edits, and be the workspace's default, so a member's ordinary chat can run it (the owner, 2026-11-18: "Allow it"; an accepted leftover, see T79).
**Residual:** a queued untrusted message delivered into a running owner's turn rides in that turn, which keeps its tool (routine runs open a new chat each, so this needs a person to queue one).
A compromised node that hosts one of the owner's chats can read up to 8 excerpts' worth per granted turn of the owner's chats on other nodes (it already holds the chats it hosts); `denied_tools = ["recall"]` or the agent's switch off removes it.
Tests: `master/tests/it/recall_http.rs` (owner, workspace, temporary chat and own chat excluded; forged node and fields; untrusted turn, Smol, temporary chat; per-turn cap; memory places), `node/tests/recall.rs` (one request for the own session, quoted answer, master refusal, `denied_tools`), `memory/src/recall.rs` (quoting and caps), `protocol` (`recall_messages_carry_words_only`), `agents/tests/agents.rs` (`recall_is_its_own_switch`).
