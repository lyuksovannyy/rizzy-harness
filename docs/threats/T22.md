# T22

## Threat

A prompt-injected model uses the harness's network clients as a relay or a way inward: `web_fetch` to an internal address or to a URL it built to carry data out, a redirect or DNS answer that points inside, a backend server that redirects a request carrying an API key

## Mitigation

**`web_fetch`:** the public-address check runs on every address the client connects to (our DNS resolver drops non-public answers, so a rebinding name cannot reach an inner address; IP-literal URLs and every redirect hop are checked by `check_url`; environment proxies are ignored). `is_public` refuses loopback, private, link-local, CGNAT, multicast, documentation, reserved IPv4 and, for IPv6, whole ranges that embed or tunnel to IPv4 rather than decoding them: `::/96` (unspecified, loopback, IPv4-compatible), SIIT, NAT64 (`64:ff9b::/32`), 6to4 (`2002::/16`), `2001::/23` (Teredo and other protocol assignments), discard-only, unique-local, link/site-local, multicast, documentation (`2001:db8::/32`, `3fff::/20`), SRv6;
IPv4-mapped addresses are judged as their IPv4 address.
**Provenance:** a URL is fetched only if it appears, spelled the same (host case, default port, fragment and IDN folded by the `url` crate; path, query, port, trailing dot and userinfo not), in the user's own words this turn or earlier, or in the output of a *successful* `web_search` or `web_fetch` call.
Never in: a file `read` returned (N-6, below), a file attached to a message (its text, name and type ride on the user message, quoted, and are not the user's words: T41), an image's name in the note that stands for an image not shown (T43), any tool's error text, `bash` output (and so `tool_output`), grep/glob/outline, memory recall and per-turn page context (they ride on the user message but are stripped from the provenance set), a sub-agent's task text (written by its parent model), or the model's own text and call arguments.
A sub-agent inherits its parent's set as it stands when the task is delegated (the user's words and the parent's successful search/fetch results; passed by the node in-process as `TurnExtra::observed`, shared by `Arc`, never from the protocol, and grandchildren inherit it the same way) and adds its own successful results; a URL the parent could not fetch is refused in the child too, so an injected parent cannot launder one through the task.
Residual: a page the model legitimately read can contain URLs, so the trusted set includes them; (a file the model wrote and then `read` can no longer plant one: N-6, below); `www.` and the bare domain count as the same host; a pasted URL can still carry data the user typed. **mem0 backend:** every id and owner id is one percent-encoded path segment or query value (`/`, `?`, `#`, `%` cannot change the path; `.` and `..` are never sent), and the client uses the same-origin redirect policy of the embeddings client, so a mem0 server cannot send `X-API-Key` to another host.
Tests: `crates/memory/tests/mem0.rs`. **`read` does not vouch for URLs** (review N-6, a condition on ADOPTION_PLAN T.3: **done** with T.3's web half, T89): `URL_SOURCES` (`crates/agent-native/src/lib.rs`) is `web_search` and `web_fetch` only, so nothing a file tool or the shell returned counts.
Reason: once `web_fetch` and the file tools share a runtime, an agent that can write files (`write`, `edit`, the shell) composes a URL with a secret in it, writes it to a file, `read`s it back, and the provenance rule is laundered in two calls; in Accept edits the write shows no card and `web_fetch` is a read, so nothing would ask, where the same exfiltration through `curl` would show a card.
A file attached to a message never vouched (T41), so no legitimate path used `read`.
What vouches in an agentic chat: a URL the person wrote, a `web_search` result, a link on a page `web_fetch` returned.
Tests: `crates/node/tests/web_tools.rs` (`a_url_in_a_folder_file_is_not_fetched`, `a_url_written_to_a_file_and_read_back_is_not_fetched`; both fail with `read` put back), `crates/agent-native/src/lib.rs` (`url_in_a_successful_search_is_observed_but_not_one_in_a_read_file`).
