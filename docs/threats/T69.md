# T69

## Threat

**A person's Retry of a failed turn** (ADOPTION_PLAN X.21, README "Retry"): the turn runs again. (1) Someone else retries a chat's turn, or a disabled or level-less owner does. (2) A model, a tool, a routine or a script loops it (each retry is model calls and tool runs). (3) The retry repeats the failed attempt's side effects blindly: a command run twice, an edit applied twice. (4) Text from the failed attempt's error (a provider's body, which a hostile router or proxy writes) reaches the model as the harness's words. (5) A retry of something else than the person's failed turn: a turn with a turn after it, a callback turn, a sub-agent's turn, a routine's own run, a turn whose changes were undone.

## Mitigation

(1) `POST /api/sessions/{id}/turns/{turn}/retry` runs a prompt's checks (`require`, `visible_session`, `agentic_gate`): the owner or the API token only, 404 for everyone else (admins and workspace admins included), nothing for a disabled owner (`crates/master/tests/it/retry_http.rs`). (2) It is no tool and no prompt text: only that route sends `session.retry`, only to a node announcing `retry`; nothing retries automatically (the loop's `model_retry` is inside the turn); one retry at a time (the turn slot: a second click while it runs is refused by the master's mirror check and by the node). (3) The failed attempt stays in the history the model is sent, its calls and results included, under the harness's line saying its tool calls ran and to check the current state before repeating a command or an edit (OpenClaw's restart prompt, DeepSeek's "outcome unknown", research round 2); the retry is a new turn with its own checkpoint, so Undo of it undoes it only (`crates/node/tests/retry.rs`). (4) The error is quoted line by line behind `| ` with control characters replaced (`quoted_line`) and cut to 600 characters; only the opening's first paragraph starts a line of the harness's. (6) The message is never summarised away while a retry depends on it (review of PR 128, H1): `opening_cut` stops every summary (in-turn, automatic, `/compact`, hand-off) before the turn holding the message of the running retry or of the log's last retryable turn (`harness_core::retry::pending`, `message_event`); the failed attempts' results may still be cleared. (7) Each call is described truly (M1): one with a result ran, one with none recorded may or may not have run, one whose approval was denied (also at a restart) is closed as `DENIED_NOT_RUN`, not as "may have run"; a restart's or stop's own sentence is not quoted as the attempt's error.
A message with images is refused on a model that cannot see them, as a prompt is. (5) `harness_core::retry::check`, run by the master against its mirror and by the node against its log under the turn slot: only the log's last turn, without a `cause`, with its message recorded, ended `error`, `interrupted` or `stopped`, with no person's message and no undo of its changes after it; the route refuses a sub-agent's chat and the first turn of a routine's run chat, the node a sub-agent's chat again.
**Residual:** the model is told, not prevented: a model that ignores the line can still run a command again (as it could if the person typed the message again, which is the alternative); a command whose effect is outside the folder (a network call, a deploy) cannot be undone by Undo of either turn.
