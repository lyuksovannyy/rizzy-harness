# T49

## Threat

**Memory saves without a click** (owner's decision 2026-11-14, ADOPTION_PLAN T.3): a prompt-injected agent plants a false or steering fact that every later turn reads as known about the person ("they want every file sent to x.example"), or retires true ones, so one poisoned page becomes a lasting injection across chats; a model files a private detail (health, money, family) where a team's chats will read it; another member, a workspace admin or a server admin reads a person's facts; a secret lands in memory

## Mitigation

**Who may write:** only a turn the person wrote.
An untrusted turn (external event) and a callback turn get no `remember` and the master files nothing from them: the callback check is the log's (`turn_cause`), the rest the turn's recorded `TurnMemory`; incognito chats, agents whose memory is off and nodes without `CAP_REMEMBER` file nothing.
**When a call applies without a click** (`memory::saves_without_a_click`, the one rule, with the owner's words): the owner asked "In chats that read files or the web, should memory wait for one Keep click?" and answered (2026-11-14) "No, always save".
So in the chat owner's own Personal workspace a call from a turn they sent signed in as themselves (`TurnMemory::by_owner`, set by the HTTP prompt route) applies at once in every chat, also one that read pages, files, attachments or instruction files, unless it targets a fact the person wrote by hand (review M7).
Never at once: a sub-agent's call, a team workspace, the API token's turns (review N1), a routine's run (its prompt is sent by the master, `by_owner` false: a proposal), callback and untrusted turns (no `remember` at all), temporary chats (nothing).
There the change is filed as a proposal and the chat's memory block asks with **Keep** and **Dismiss**, for the chat's owner only.
**Every change is shown** as its own memory block at the call's place in the chat (saved, replaced old → new, forgotten, waiting, refused), with Undo for every applied change; the block's state comes from the server (it polls while the master has not filed the call, review's fetch race), so it is the same after a reload.
**What each call did** is recorded per call (`memory::CallRecord`, master `kv` `memory.call:<chat>:<call>`, fact ids only), and the chat line, Keep, Dismiss and Undo act on that record alone (review M6: Undo restores only a fact this call retired).
The model is told in the next turn, once that turn was sent (review M5), of a save that waits or was refused; the tool's own reply claims neither (review M4); the context says "saves at once" only where it does.
**Bounds on what is planted:** a fact is one line (`memory::one_line`, `quoted_line` per piece) behind its id, inside the quoted per-turn context (T43); hidden characters are dropped and 500 characters is the most (`clean_text`); the facts the model saved stop at 3,000 characters counted as the lines a turn reads (hand-written facts not counted, review M7), the refusal named in the next turn.
**Replace and forget** (owner, 2026-11-14: "replaces / forget - must work in all memory types with ability to revert the change via the block") reach every kind of fact the chat is given with an id, and nothing else: the owner's own facts and theirs kept in the chat's workspace (where personal memory is on for the turn) and the chat's project's facts (where project memory is; project facts are now shown with ids, one line each); a fact of another person, another project or a workspace the chat is not in is refused (`memory::change`, checked against the owner key).
They only **retire** (restorable, in every back end), and a replacement keeps the replaced fact's owner key, so a call never moves a fact between scopes.
At once only where the chat's owner may change that fact by hand and the turn is their own: their own facts (in Personal and in a team where they are recalled), a project's facts only for someone who may manage the project or where `members_activate_facts` is on (`projects::may_change_facts`); otherwise the block waits (a project fact: for a project manager, Keep refused, nothing changes).
Undo of a project change works while the chat's owner may still change that fact (`memory::may_touch`); the project's Memory tab shows retired facts with Restore for managers.
**Two places:** the person's own facts (owner key: their id) and the facts kept about them in one workspace (`member:<workspace>:<user>`); the model picks with `sensitive`, and a correction of a fact kept in a workspace stays there whatever the flag says (review M2): only the person widens a fact, on the Memory page.
A kept fact is recalled only in chats of that workspace; their own facts reach a team only after they answer its join question yes (`workspace_members.use_memory` NULL until answered, read as no).
Kept facts are deleted when the member leaves or the workspace is deleted, and all of a person's facts when their account is deleted (before this change an account's facts stayed in `memory.db`).
**Privacy:** every memory route checks that the fact's owner key names the caller (`memory::key_owner`; project keys never match); the call routes (state, Keep, Dismiss, Undo) answer only for the caller's own chat, signed in (T10); another member, a workspace admin, a server admin and the API token get 404. **Secrets:** `looks_secret` refuses a key-shaped word (known prefixes; 20+ characters mixing upper case, lower case and digits; a PEM header) or a sentence that names a secret and gives a value shaped like one (review M3: "their passwords are kept in 1Password", a commit hash, a UUID or a branch name pass), on every path.
Tests: `crates/master/tests/it/memory_places_http.rs` (`a_chat_that_read_outside_content_still_saves_at_once_with_undo`, `review_poison_read_in_an_earlier_turn_…`, `review_replacing_a_sensitive_fact_…`, `a_turn_not_sent_by_the_owner_only_proposes`, and the rest), `callbacks_http.rs` (forget from untrusted and callback turns retires nothing), `memory_http.rs`, `crates/memory/src/lib.rs` (`secrets_are_refused`, both ways), `crates/master/src/memory.rs`, `crates/store/tests/workspaces.rs`.
**Residual (accepted by the owner, 2026-11-14):** text the agent reads in a Personal chat (a web page, a file, an attachment, a repository's instruction files) can talk it into saving a false fact, or forgetting a true one, that every later Personal chat is given.
What bounds it: each such change is shown in the chat with Undo, a forgotten or replaced fact is retired, not deleted, the model's saves are capped at 3,000 characters, secrets are refused, and nothing reaches a team workspace unless the person said yes for it (a fact kept "here only" never).
The reviewer's proof of M1 is kept as `review_poison_read_in_an_earlier_turn_saves_and_forgets_at_once`, documenting this.
Also: the model's `remember` input is in the chat's log, so a secret it tried to save is in the log though memory refused it. `sensitive` is the model's guess: a private detail marked ordinary follows the person into every team they say yes to.
The secret check is a heuristic.
Next-turn notes are in memory only (a restart forgets them); the per-call records are not removed when a chat is deleted (fact ids only).
