# T80

## Threat

**Which agents of a workspace may use which skill or MCP server** (ADOPTION_PLAN X.34 step A, README "Plugins: who may use which skill and connector", docs/agent-pages.md "Skills", "Connectors"): nodes announce the names of their own skills and servers (`node.plugins`), a workspace's editors mark an item Shared (no row) or Assigned to agents of its set (`plugin_access`), and the master sends each spec the names that agent may not use.
Abuse cases: (a) an Assigned item reaches an agent it is not assigned to: directly, as a sub-agent, through `/name`, through an alias, after the agent is renamed or deleted and remade, or on a node that does not read the lists; (b) one workspace's settings change another workspace's chats on a node both use; (c) a node announces 100,000 names, names with control or hidden characters, a look-alike of another node's item, or a new list every second, or two nodes have one name with different content; (d) a master (or a forged spec) uses the new fields to widen: start a server or add a skill the node does not have, or get past node.toml's `denied_tools`; (e) a member without `settings` changes access, or an editor names another workspace's agent, an alias or an unknown id; (f) announced text reaches the browser as markup

## Mitigation

**Deny-only, decided by the node:** `AgentSpec::deny_skills` and `deny_mcp_servers` are names to withhold, never names to load or start; the master puts them on the turn's spec and on every delegate's, each by its own canonical id (`plugins::Assignments::deny`, in `Resolver::agent_spec_with`, so every path that sends a spec gets them: create, prompt, retry, callback, the agent switch); an alias resolves to its agent before; they enter the prompt hash.
The node leaves a denied skill out of the catalogue, refuses it in the `skill` tool and answers a person's `/name` of it with a `[harness]` line, by name whatever its origin (a repository's skill of that name does not stand in), and, once anything is denied to the agent (also a name discovery did not list: `a_denied_name_that_is_not_listed_still_narrows_the_grants`), grants the shell each kept node skill's own folder and never a whole root, so a same-named copy discovery did not use, a refused folder or any other file in a root is not granted either (`skills::withhold`; review of PR 147, M1); a denied server is not started for the turn and its tools are neither offered nor callable (`SessionMcp::load` skips it; `AgentSpec::allows_tool` refuses `mcp__<server>__*` by the server part, which cleaning and cutting a public name never change).
A sub-agent follows its own spec's lists (its catalogue is built from its own spec, and its own `deny_mcp_servers` decides which of its chat's servers its foreground turns may use, X.34 step C, T47); nothing here grants any.
**Old nodes fail closed:** a node without the `plugin-access` capability would ignore the lists, so `send_command` withholds the whole `skill` tool (or `mcp`) through `deny_tools` from every spec with a skill (or server) denial (`plugins::fail_closed`), and the screen names such nodes; settings the master cannot read (the Plugins rows, or the workspace itself in `resolver_for`) withhold both for the turn (review of PR 147, M2).
The node bounds the lists itself: over 1,000 names or a name over 128 bytes withholds the whole tool from that spec (`LimitsPolicy::bound_delegation`), nothing cut.
**Per workspace:** the lists come from the chat's own workspace (`resolver_in`); no row is Shared, so nothing changes until an editor chooses; rows go with their workspace (foreign key cascade).
**Edits:** the workspace's `settings` permission (404 for a non-member); agents by id of that workspace's set (server and workspace agents; an alias, another workspace's agent or an unknown id is 400); names by the node's own rules (`valid_skill_name`, `valid_mcp_server_name`: ASCII only); 200 Assigned items per workspace, 100 agents per item, 16 KiB per list; deleting an agent removes it from every list of its scope (`plugin_access_forget_agent`), so one remade with its id starts with nothing.
**Announcements:** names and one-line descriptions only (no path, command, argument or environment), cleaned and bounded on the master whatever a node sends (`NodePlugins::bounded`: 300 skills, 64 servers, 64 KiB, descriptions one `clean_line` of 200 characters, invalid names and duplicates counted, not shown); the first per link is kept, a second ignored; the node reads its list once per runtime, after hello and without holding the link (a hung folder costs one thread, not one per reconnect), so a list changes only with a node restart; the setting is by name, so the same name on two nodes is one item (the screen shows each node and says when descriptions differ); everything is rendered as text.
Tests: `core/src/agent.rs` (`a_denied_server_takes_its_tools_and_nothing_else`), `protocol/src/lib.rs` (`announced_plugins_are_bounded_and_clean`), `tools/tests/skills.rs` (`a_withheld_skill_leaves_the_list_the_tool_the_slash_and_the_shell`), `tools/tests/mcp.rs` (`a_denied_server_is_neither_started_nor_offered`), `node/tests/skills.rs` (withheld skill, sub-agent's own list, the announcement), `node/tests/mcp.rs` (a denied server not started nor callable; names only announced), `store/tests/workspaces.rs`, `master/src/plugins.rs`, `master/tests/it/plugins_http.rs` (every agent and sub-agent, alias, other workspace, Personal, Shared again, editors, ids, names, delete and remake, an old node, hostile announcements), `agents/tests/agents.rs` (the Skills switch), `web/src/components/plugins.test.tsx`, `web/e2e/plugins.cjs`; after the review of PR 147: `cli/tests/skill_roots.rs` (`a_withheld_skill_is_not_readable_from_the_shell`, real bubblewrap), `node/tests/skills.rs` (`the_shell_is_not_granted_a_withheld_skills_folder`, `the_announcement_is_read_once_and_follows_hello`), `node/src/policy.rs` (`oversized_deny_lists_withhold_the_whole_tool`), `master/tests/it/plugins_http.rs` (`settings_that_cannot_be_read_withhold_skills_and_connectors`).
**Residual:** a skill body or a server's output an allowed agent got stays in the chat's history when another agent takes the next turn; in a `host` chat the shell reads what the node's user can, so a withheld node skill's files are not hidden from it, and a repository's skill files stay readable as repository files; the setting is by name, so a node that renames a skill or server moves it out of its Assigned row (it becomes a new, Shared name) and two folders linked to one skill under two names are two items; a node's list is read once per runtime, so a skill or server added since shows after the node restarts (it is usable, Shared, before); on an old node an agent with any denial loses the whole tool.
A `[skills] roots` folder under the sandbox's system read set (`/usr`, `/etc`, `/opt`, …, `tools/src/sandbox.rs`) stays readable to every sandboxed shell, so withholding does not hide such a skill's files. `node.plugins` is the first message a node sends unasked that an older master does not know: such a master drops the link on it (allowed before the first tag, said in the protocol's header).
A turn that only reads queued messages reuses the previous turn's spec, and a running background sub-agent keeps the lists it started with, so a change of assignment lands one turn late there.
A chat outside any workspace (`workspace_id` none, as the API token can make) carries no lists.
