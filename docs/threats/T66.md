# T66

## Threat

**The read-only shell** (ADOPTION_PLAN T.7, docs/read-only-shell.md): a command that must not change anything (plan mode; read-only agents, T70) writes the chat's folder anyway: `touch`, `sed -i`, a here-doc, `python -c`, git's index or refs, a link from its temp folder into the folder, `/proc/self/cwd`, `chmod`, a remount, a `[sandbox] write` entry, or fills a temp folder on the node's disk

## Mitigation

Enforced by the file view, never by reading the command (no parser, no safe-command list): contained in bubblewrap with every grant read-only (the folder, node.toml's `read` and `write` entries, a sub-agent's folder), the root read-only, only a `/tmp` tmpfs of the command's own namespace writable (`[sandbox] read_only_tmp_mib`, 1 GiB by default, `--size`; gone with the command; the session's temp folder not granted), Landlock inside with the same lists as a second layer, `GIT_OPTIONAL_LOCKS=0`.
Where the node has no containment, or its bubblewrap cannot size a tmpfs, there is no read-only shell (`Confinement::read_only_shell` says why): Landlock alone does not cover `chmod`, `chown`, `utime` or xattrs, so it is never offered as read-only.
Tests: `crates/cli/tests/read_only_shell.rs` (every write checked from outside, a control that the same command writes with the shell writable, the binds alone without Landlock, a background command, the bounded `/tmp`, the refusal without a containment).
Where the containment shares this machine's `/proc` (`Form::SharedProc`), another process's `/proc/<pid>/root` leads past the binds and only Landlock stops it: there the read-only shell exists only with `[sandbox] mode = "required"`. Every sandboxed command (not only this shell) runs with core dumps off (`RLIMIT_CORE` 0, soft and hard, set by `sandbox-exec`): the host's core pattern may pipe a dump to a handler outside the sandbox. `CARGO_TARGET_DIR` points into that `/tmp`, so `cargo build`/`test` work with the toolchain folders granted read (T70); toolchains that must write their home or the folder (`npm install`) cannot.
Residuals: reads and the network are as for any command (read-only is not secrecy); a background command started before is its own; the temp folder's size in host memory per running read-only command, background ones included, in no process's RSS (no cgroup per command), returned when it ends.
**Review of PR 131 (one profile: plan mode and read-only agents):** the tmpfs is mounted where no grant lies beneath it (`read_only_tmp_dir`: `/tmp`, or `/.harness-tmp` when the chat's folder is under the host's `/tmp`), because a Landlock rule covers everything beneath its folder and the tmpfs's write rule had covered such a folder, so Landlock was no second layer there and a pathname Unix socket in the folder was reachable (`a_folder_under_tmp_keeps_landlock_as_the_second_layer`); pathname sockets are refused by Landlock from ABI 9 (`LANDLOCK_ACCESS_FS_RESOLVE_UNIX`), older kernels keep that residual.
**No network by default** (`[sandbox] read_only_network = false`, never wider than `network`): a network namespace of its own (its own loopback works), Landlock's TCP rules where bubblewrap cannot make one (UDP open then); a behaviour change for plan mode (`the_read_only_shell_has_no_network_unless_node_toml_says_so`).
The size is node.toml's (`read_only_tmp_mib`, 256 MiB default; `the_temp_folder_is_host_memory_until_the_command_ends`)
