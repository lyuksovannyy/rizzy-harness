# T91

## Threat

**An agent reads its own chat's earlier turns in full** (ADOPTION_PLAN X.47, README "Reading earlier messages"): a tool that returns the log's old text to the model could show it what was taken out of its sight on purpose (a rewound range, an image or thinking a provider refused, another chat of the person or of someone else), put old text back in front of it as if the harness had just written it (a tool result or a file that imitates a harness note or one of this tool's labels), or cost the turn unbounded output; and a call that wrote anything or went to the master would be a new way to change the chat or to ask the server about it

## Mitigation

**It is read-only and local.**
`history` runs on the node, reads the session's own log and image store through the session it was started for (`harness_node::history::OwnHistory`, built from the session id of the turn; a sub-agent's turn holds its own id), and writes nothing: no event of its own beyond the call and its result, no file, no master round trip (`crates/node/tests/history.rs`: a sub-agent's chat reads only its own log, nothing of its parent's; `denied_tools = ["history"]` refuses it and nothing is read).
Nothing in the call names a session, a person or a workspace: its arguments are numbers, one call id, a page and a search text.
**It shows nothing the model would not have been sent without compaction.**
The conversation is the model's own rebuild (`harness_agent_native::rebuild_spans` with `Rebuild::unshortened`), not a second reading of the log: a rewound range is absent from the index, the search and a turn (turn numbers are those of the visible turns, so they change after a rewind), withheld images stay withheld and are refused with the reason, thinking is never printed, and of parallel variants only the chosen one is there (`crates/agent-native/src/history_tests.rs`).
**Old content comes back as quoted data, never as a harness line.**
Every line written then (the person's, the model's, a tool's, an attachment's) is quoted behind `| ` line by line (`quoted_line`: any other line break or control character becomes U+FFFD), and the only lines that do not start with the quote are this tool's own labels, which never start with the harness's lead; a result that imitates a harness note, a label or a header comes back as quoted text of its result (`old_text_imitating_a_harness_note_or_a_label_comes_back_quoted`).
Names and the person's first words in an index line are made one line with `shown_name` (the quote marks they hold are read as `'`).
A `history` call's own earlier results are shown as "an earlier history read", so a turn never holds a copy of a copy, and its calls are left out of `search`.
**Output is bounded.**
Every answer is inside `harness_tools::RESULT_BUDGET` (the tool-result budget the other tools use, so the loop never cuts it): the index is 100 turns a page, a turn is paged by what fits, a result, attachment or message over 4,000 characters is cut with the line that reads all of it in parts, a search lists at most 20 turns and refuses fewer than 3 characters (tests with a 5,000-turn chat, a 5 MB result and 300 calls in one turn).
**An image goes through the same gate as `read`'s.**
The call returns it as `ToolOutcome::image`: the loop shows it only to a model that takes images, within the per-step and per-turn caps, keeps it with the chat and records a reference, never bytes; the bytes pass `harness_tools::image_of` (the magic number, size and side checks of `read`); a model without vision gets the harness's line saying so, bytes the store no longer has are said so (`crates/agent-native/tests/history_tool.rs`).
**It has its own per-agent switch** (`Features.history`, on when absent: it shows an agent only what it was sent once, in the one chat it is in): the tool is offered only to an agent whose list holds it, and a forged call by one without it is an unknown tool before anything is read (`crates/agents/tests/agents.rs::the_history_switch`, `it_is_offered_only_with_the_switch_and_a_forged_call_is_refused`).
Its risk is read-only, it is on the shared read-only list (plan mode runs it, an agent with only read tools stays read-only), and every call is recorded and scrubbed like any tool call.
**Not undone, stated plainly:** a person's secret that was in the chat is in the log and the agent can read it again here (the scrubber already ran on what was recorded); text of files and pages in old results is still untrusted and the tool's description says so; `history` shows a rewound turn nowhere, but the `recall` tool still can (T90).
Tests: `crates/agent-native/src/history_tests.rs`, `crates/agent-native/tests/history_tool.rs`, `crates/node/tests/history.rs`, `crates/agents/tests/agents.rs`, `web/src/components/agents.test.tsx`.
