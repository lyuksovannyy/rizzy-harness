# T58

## Threat

A member learns when someone else works (a timing leak against "chats are private to their owner, in every workspace, for admins too"; live test, 2026-11-15): the UI sockets' content-free nudges (`sessions_changed`, `memory_changed`, `projects_changed`, `workspaces_changed`, `<topic>_changed`) went to every open socket, so member B's browser was told the moment member A's private chat started or ended a turn, was renamed, or A saved a personal fact

## Mitigation

Every nudge names its audience (`master::Audience`), resolved for each socket when it is sent (`ws::reaches`), so a member removed in between is not told: a chat's changes (its turns' structural events, title, unread and attention marks, deletion, its project) its owner only (`Chat`, or `User` read before a deletion); a person's memory that person; a proposal from a chat not yet sent on its proposer only; a workspace's memory, settings, members, projects, boards, templates and shared artifacts its members (`Workspace`, `Project`); a deleted workspace its former members by account; an account's change (role, ceiling, disabled, deleted) that account and the members of its workspaces; owner-less memory the API token only.
Only these go to every signed-in socket (`Everyone`): `nodes_changed` (nodes are a server-wide list; a node coming or going says nothing about a chat), the server's workspace policy, and the hourly artifact sweep.
The API token's socket is told everything, as it may read everything (T29).
Nudges stay content-free; the channel stays bounded; a socket that lagged is told to refetch its own views, which says nothing about anyone.
Tests: `crates/master/tests/it/live_audience_http.rs` (silence is asserted with a marker the observer is entitled to, first in, first out, not with a sleep), `seams_http::changed_topics_reach_only_their_owner`, `media_http::media_changed_reaches_only_the_owner`.
Residual: all nudges share one bounded channel, so a socket that lags because of others' traffic learns that there was traffic; whether a socket may be told is read from the store per nudge and socket (one small read each); when a person sends a memory proposal on, or one is decided or dismissed, the workspace's memory nudge goes to all its members though only those who may decide it can see the proposal, so a plain member's page refetches and shows nothing new (an action in shared memory, not chat activity; review of the fix).
