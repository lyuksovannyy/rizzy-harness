# T102

## Threat

**An agent opens a pull request with the chat owner's connection** (ADOPTION_PLAN X.27; README "Opening a pull request"; `docs/forge-pr.md`; `crates/master/src/forge_pr.rs`, `forge_push.rs` `release`, `crates/node/src/session_push.rs` `run_pr`, `crates/tools/src/pull_request.rs`): the request sent differs from the card the person allowed, a click is spent on another card or twice, the token leaks (to the node, another host, an event, a log or audit line, an error or the page), the pull request lands in another repository, or the forge's answer smuggles text, floods or stalls the server

## Mitigation

**Where it runs:** on the master as a built-in service; the node shows the card and sends `forge.pull_request` with the approval id only; the token never leaves the master for this tool.
**Content binding:** the master creates the pull request from the input of the one `tool_call_started` the approval names, read from its own mirror (`Store::approval_call`), never from the approval event's own `input` field and never from the node's request; the page draws that same event's input on the card; the input passes `parse_pr` (keys head, base, title, body, draft only; branch names by `valid_branch`, head not base; title 1 to 256 characters, one line, no control character; body at most 20,000 characters, no control character but newline and tab; hidden and bidirectional characters kept and shown).
**Click binding:** push's (T101): the Allow the master relayed from the chat's owner signed in, recorded only when the approval and its call both name the tool, each id unique in the log and within `[A-Za-z0-9_-]{1,128}`, the card unanswered; one token or pull request per approval id ever; the page encodes ids in paths and draws mismatched, reused or out-of-rule cards invalid, Deny only.
**Who and where:** the shared `release` checks (node runs the session, top-level non-temporary chat, turn not a callback, tool not withheld, agent switch, no foreign actor, owner's account and level now, project source, host and connection unchanged); only the project's recorded source repository; one request per chat at a time; 5 per chat per hour.
**Outbound:** the listing's client (https, public addresses unless the host entry allows a private one, same-origin redirects, no proxy, the call time limit), 256 KiB of answer, a redirect elsewhere is an error; the default branch asked with one GET only when no base was given, after the Allow; the forge's error text cleaned of control and format characters and the token, cut to 300 characters; the address of the pull request passed only when it parses as an http(s) URL of at most 512 bytes, shown as quoted text.
Tests: `crates/master/tests/logs/forge_push_http.rs` (made from the mirror's call input when the approval's own input differs, mutation-checked; a missing base; a reused id, a retitled call, a push card's click, no click, an id outside the rule; bad input never reaches the forge; already open, a hostile error text, 5 MB, a redirect and a slow forge; the sixth in an hour; an API-token turn; the token nowhere), `crates/node/src/forge_push_runtime_tests.rs` (the card in Auto with the call's input and no wider grant, the request names only the approval, Deny asks nothing, not offered where denied or without a target), `crates/core/src/forge.rs` (`pull_request_input`), `crates/agents/tests/agents.rs`, `web/src/components/approvalpreview.test.tsx`, `agents.test.tsx`.
**Residual:** a compromised node that runs the chat can make the request say what it likes, and the person sees exactly that; any host chat on the node can read the node's key (T101); the forge's default branch and the head branch's existence are the forge's word; the limits are per process and reset on restart; the person's GitHub token may lack the scope to open pull requests (the error says which).
