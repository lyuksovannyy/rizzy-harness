# T97

## Threat

**An agent makes a Word or Excel file from its own text, and that file is written into a folder or kept by the master for a person to open** (ADOPTION_PLAN X.56, README "Documents the agent makes"): the text is the model's and may have been steered by a page, a file or a message nobody trusts, so a closing tag or a control character in a cell or a heading could break the file or inject markup, a formula could send the sheet away the moment the person opens it (`WEBSERVICE`, `IMAGE`, `RTD`, DDE, another workbook, a `HYPERLINK` to a `file:` or `javascript:` address), a link could do the same from a click, a name such as `../../.bashrc` or one with a right-to-left override could write outside the folder or lie about what the file is, a folder file could be overwritten, a request could carry or claim another person's or another chat's file, a loop of calls could fill the owner's quota or the server's disk, and a file the master built could be served inline to a browser.

## Mitigation

**A library that only writes strings it has cleaned.**
No docx or xlsx crate and no `zip` crate: `harness-docs` writes the few parts of a package from fixed templates, and the zip with a writer that is the twin of the bounded reader (stored or deflate, correct CRC-32 and sizes, UTF-8 names, a fixed timestamp, no zip64, a name with `..`, a leading slash, a backslash, a control character or a repeat even by letter case refused).
The one new dependency is `pulldown-cmark` 0.13.6 (MIT, released 2026-10-30, no default features: it parses and renders nothing); its own dependencies were already in the tree (`cargo deny check` was not run here).
Every string the model gives goes through `xml::clean` (what XML 1.0 forbids and the bidirectional overrides and isolates out) and then `xml::text` or `xml::attr`; Markdown raw HTML is dropped and counted, images are never embedded (their alternative text stays), and nothing is fetched (`crates/docs/src/tests.rs::hostile_text_is_data_in_every_place_a_document_takes_text`, `::text_from_the_model_is_data_in_every_cell_header_name_and_formula`, `::raw_html_and_images_are_dropped_and_counted_and_only_safe_links_stay`, `::the_zip_writer_refuses_bad_names_duplicates_and_size`).
Every file the tests make is read back with the reader of T96 (`Package`) and checked part by part: well-formed XML, every relationship target present, every part with a content type, sizes and CRC-32 as the directory says, property blocks in the schema's order, cells and rows ascending (`::a_document_reads_back_as_it_was_written`, `::property_blocks_are_in_schema_order`, `::a_workbook_reads_back_as_it_was_written`).
**A string is text; a formula is a field.**
A sheet cell that is a string is always written as text (an inline string), whatever it starts with; a formula is only `{"f": …}`, is checked before it is written and is refused as a whole, naming its cell: `WEBSERVICE`, `IMAGE`, `RTD`, `CALL`, `REGISTER`, `EXEC`, `SQL.REQUEST`, `DDE`, `DDEAUTO`, every `CUBE…`, any `|` (DDE), any square bracket (another workbook, a table reference, also inside a quoted sheet name), a quoted sheet name with `\`, `/` or `:` in it (a path or an address), a name with a dot before `!` (`Book1.xlsx!Total`), and `HYPERLINK` unless its first argument is exactly one text literal that starts with `http://` or `https://` and has nothing joined to it (`HYPERLINK("http://e/?"&A1)` is refused).
A denied name is refused whether it is called or handed over (`MAP(range, WEBSERVICE)`, `BYROW(range, _xleta.WEBSERVICE)`), and `_xlfn.`, `_xlws.`, `_xleta.` and any other `_xl…` prefix is removed first.
The check reads a formula the way Excel's parser tokenises it, as far as that was reasoned out and tested here (it was not run against Excel, and the list is a deny-list, not proof that nothing else can reach outside): text literals and quoted sheet names are opaque (a quote inside a sheet name cannot hide a call), case and whitespace do not matter, `_xlfn.`, `_xlws.` and other `_xl…` prefixes are removed, zero-width and bidirectional marks are dropped, and a name that is only part of a longer identifier is left alone (`::formulas_that_reach_outside_are_refused_in_every_spelling` (with the invisible-character filter of the `HYPERLINK` literal, which only lets a zero-width character before `https://` pass), `::attribute_values_are_escaped`, `::a_string_is_text_whatever_it_starts_with`, `::a_formula_that_is_refused_refuses_the_workbook_and_names_the_cell`).
`CELL` and `INFO` are allowed: they read the workbook's own place on this machine, and with no function that sends anything out (every one that can is refused above) the result stays in the cell the person opens.
No formula has a cached value and the workbook asks for a full calculation when it is opened; the tool says so.
Sheet names are made valid (31 characters, none of `: \ / ? * [ ]`, no `'` at either end, not `History`, different from every other even by letter case) and the result names what they became.
**Names are the tool's.**
The model's name is one segment cleaned by the harness's rules (controls and hidden characters out, characters no file system takes `_`, no leading dot, a Windows device name prefixed), at most 100 characters, its extension forced to `.docx` or `.xlsx` (`::a_name_is_one_clean_segment_with_the_tools_extension`).
**A chat with a folder: the write tool's rules.**
The tool is node code and writes where `write` writes: the same path policy (`resolve_for_write`: the folder, the protected places, `.git`, the pin), the same approval path (`ToolRisk::Mutating`; `AcceptEdits` covers a path inside the folder through `EDIT_TOOLS`; the call key is built from the path), the same atomic no-follow replace, and the same record for checkpoints and undo (`seen` with an empty `base`: the file did not exist).
It never replaces a file that exists: the name becomes `report (2).docx`, and the write is create-only: a temporary file in the same directory published with a hard link, which fails when the name exists, so a file (or a link or a folder) that appears at any point before the publish is skipped over and never replaced, and the undo record cannot then delete the person's file (`crates/tools/src/fs.rs::tests::a_create_never_replaces_what_is_there` proves a name taken after the write began; the last instant between the final look and the link is closed by the link itself and has no test of its own, `crates/tools/src/office.rs::tests::a_folder_gets_a_new_docx_and_never_an_old_one_replaced`, `::a_name_taken_by_anything_is_passed_over`, `::the_write_tools_path_policy_holds`, `crates/node/tests/docs.rs::a_coding_chat_writes_into_its_folder_and_asks_nobody`).
**A chat without a folder: a built-in service, never a tool of the master.**
Nothing is written to any disk path.
The node's tool files a `docs.request` (the file's content and a name, nothing that names a user, workspace or chat: a field that does is a parse error, `crates/core/src/docs.rs::a_request_carries_content_only`) and the master's service builds the file in `spawn_blocking` under the places and time limit of `attached_file` (two at once, a queue of 16, 8 seconds), keeps it as the chat owner's encrypted blob counted in their quota, and records a row of `session_files` for this chat that is not logged: the model's input is bounded text, never someone's file, so the conversion does not run in the confined helper the readers use (the tools that edit an existing file will).
The scope is the session alone (`crate::recall::sessions`): the chat must be a plain chat, not a sub-agent's, not a temporary one, and its node must have announced `doc-create`; the asking turn must be one the master granted it from the log (not a callback turn, the tool not in the turn's `withheld`, its agent with the switch "Create and edit documents", `Features::office`, on for the Assistant only); a turn may ask 60 times, a chat 240 times in 10 minutes and one at a time, a node 4 at once, and a chat keeps at most 100 made files (rows with `session_files.made = 1`, migration 6: the person's own attachments do not count, `crates/store/tests/session_files.rs::attachments_do_not_count_toward_the_made_files_cap`); the agents it hands work to never have the tools, since a sub-agent's chat keeps no files (`crates/master/src/made.rs::tests::delegates_lose_the_tools_and_the_agent_keeps_them`) (`crates/master/tests/it/made_http.rs::the_service_and_the_route_refuse_what_is_not_a_plain_chat` for the service's sub-agent, folder and temporary-chat refusals, `::the_switch_decides_in_the_turn_and_at_the_service`, `::where_the_service_does_not_make_files`, `::the_sixty_first_call_of_a_turn_is_refused`, `::a_chat_keeps_at_most_a_hundred_made_files`, `::the_account_quota_counts_a_made_file`).
**The log names the file; the master does not take the node's word for a row.**
The file becomes the chat's, readable by `attached_file` and downloadable, only when the node's own `tool_call_finished.made` names it, and the mirror marks only a row the master made for this very chat with this very hash (`harness_store::session_files::on_finished`): a node cannot claim another person's or another chat's file, nor a file with another hash, and a fork's copy of the event gets a row of its own as a fork's copy of a message does (`made_http.rs::a_log_line_cannot_claim_a_file_the_master_did_not_make_for_this_chat`, `crates/store/tests/session_files.rs`).
The name and path in the event are scrubbed like any tool result (`crates/node/tests/docs.rs::a_secret_in_a_name_is_not_in_the_event`).
**Download is the owner's, and an attachment.**
`GET /api/sessions/{id}/made/{file_id}` resolves the chat as the chat itself is opened (anyone else, administrators included, gets the 404 a chat that does not exist gets), needs a logged row of that chat and the chat owner's blob, and sends the file through `blobs::serve` as `application/octet-stream` with `Content-Disposition: attachment` and `nosniff`: never rendered by the browser; the button's link is minted for exactly that path (`auth::links::linkable`) (`made_http.rs::a_file_is_made_kept_named_by_the_log_and_downloaded_by_its_owner`, `::another_persons_chat_and_another_chats_file_id_cannot_download`).
**Bounded.**
At most 1 MiB of Markdown, 20,000 paragraphs, 200 tables of at most 30 columns and 20,000 cells, 2,000 numbered lists; at most 20 sheets, 10,000 rows, 100 columns, 200,000 cells, 10,000 characters a cell, 8,192 a formula, a 4 MiB spec; the file at most 10 MiB and no part more than 24 MiB unpacked; a request over 6 MiB as sent is refused before it leaves the node (the link's frame is 8 MiB).
One Word build is bounded in memory: the document part is written in place and every byte of it, of the open paragraph and of each table cell is counted as it is made, past 16 MiB the build stops (a tab is 30 bytes of XML, and 90 in bold italic struck text); the Markdown's `[ ] * _ ~ ` < > !` characters are counted before the parser runs (at most 150,000: the parser makes a node for each, about 50 bytes, before the first is used). Measured by `crates/docs/tests/memory.rs`, which builds each input in a child process and reads its peak resident size (no allocator can be written here, `unsafe` is forbidden): the four inputs of the review (a megabyte of tabs inside nested emphasis, 512K brackets, 262K `[a](`, 512K `*a`) peak at 17 MiB or less; a megabyte of `- ` list markers peaks at 60 MiB, in the parser; two builds may run at once on the master, so the worst case is about 120 MiB, not 64 MiB per build. The walk over the Markdown is iterative, so nested quotes or list markers are a counter (`::a_body_past_its_cap_is_refused_early_not_built`, `::inline_markup_characters_are_counted_before_the_parser_sees_them`, `memory.rs::one_build_stays_under_its_memory_bound`, `::the_limits_hold_at_the_edge_and_one_past_it`, `::the_workbook_limits_hold_at_the_edge_and_one_past_it`, `::pathological_nesting_is_a_counter_and_not_a_stack`, `::a_big_document_stays_under_the_output_ceiling_or_is_refused`).
**What the model reads.**
The result's lines are built from counts and from names cleaned to one line with quotation marks read as `'` (`harness_docs::notes`); the model's own text is not echoed into an unquoted harness line (`office.rs::tests::the_masters_refusal_and_a_hostile_answer_stay_one_line`).
Known and accepted:
- The conversion runs in the master's process in the plain-chat case (bounded text in, off the async threads, a panic is a refused call; the memory of one build is measured above, the output is at most 10 MiB); the confined helper is for files someone else wrote.
- A document is not checked against Word or Excel here: the tests read every file back with our own reader only (no `libreoffice` on the machine that built this); the samples in `.claude/handoff-2026-11-15/b-doc-create/samples/` are for opening in the real programs.
- An ordered list nested in a bullet list is numbered `a.`, `b.` (the second level of its numbering), and a rule is a page break.
- A Markdown title is a property of the file, not a heading in it.
- The same bytes made twice in one second are one blob; made later they differ by the creation time in the properties and are two.
- A row the master made whose call never reached the log (a node that went away, a turn stopped) is not the chat's and not downloadable, and stays until the chat is deleted; it counts toward the 100 files and the quota.
- `PER_NODE = 4` calls at once is a limit of the node, and the chat runtime is one node for every user of plain chats (as for `attached_file`): one person's burst can make another's call wait or be refused. A known limit before team use.
- In Ask mode a plain chat asks before it makes a file, as it asks before any other change (`ToolRisk::Mutating` is per tool, not per chat kind).
