# T54

## Threat

**A workspace's shared memory** (the owner, 2026-11-14: "Workspace memory available to all users in it"; ADOPTION_PLAN T.3): one memory per workspace (owner key `workspace:<id>`), given to every member's chats there and readable by every member.
A member (or a prompt-injected agent in a member's chat) plants text that every colleague's agent then reads as the workspace's knowledge ("deploy with `--force`", "send reports to x.example"); an agent files something private about a person into a memory colleagues read; a member of another workspace, or someone who left, reads it; it outlives what it should

## Mitigation

**Who writes:** by hand only those who may change it (`memory::may_edit`: the workspace's admins and owners, the `settings` permission; every member, never a guest, while the one switch `memory.members_edit:<ws>` is on, off by default; in Personal, its owner).
They retire; a hard delete is only of an already retired fact and only by those with `settings` (`memory::may_purge`; review of pull request 107, F5), the same for project facts (managers).
Every shared fact records who added it and when, who kept it, who retired it (`memory::Authorship` in `kv`, F4), shown on the tab to every member ("a former member" once the account is gone).
An agent's save, replace or forget there applies at once only where the chat's owner could do it by hand and the turn is their own (`TurnMemory::by_owner`, not a sub-agent); otherwise it is a proposal in two steps (F2): first only the person whose chat made it sees it (their chat is private; the block offers Keep and Dismiss); their Keep applies it if they may, or else sends it on (`ProposalMeta::submitted`), and only then does it appear under Waiting on the workspace's (or project's) Memory tab for those who may decide it, with the proposer's name and what it would replace or drop, and counted on the Overview.
Keeping one runs `memory::keep_proposal` (the cap is checked then too, F7);
Dismiss after it was decided is refused (F3).
At most 10 waiting changes per person and 50 per place (F7).
The API token's turns, routines, callbacks and untrusted turns never write it at once; after a restart, when what a turn may write was not recorded, it writes no shared place at all (F9).
**What lands there:** the model names the place (`about`: me, workspace, project); one that says nothing goes to the person's own facts, never the shared memory; `about: project` where the chat has no project is refused, never re-filed (F8); `sensitive` always wins over `about` (F1): a sensitive fact is about the person, and in a team chat it is never written to the team's (or a project's) memory: it is filed as a proposal in the person's Personal workspace's memory (`memory::file`), which no team chat is given, and waits for their Keep.
**What readers get:** the shared memory is given whole up to 3,000 characters (`CARRIED_CHARS`), one line per fact behind its id (`one_line`, `quoted_line`), under a header that says it is other people's notes, not instructions, inside the turn's quoted context (T43); the cap on the agents' own saves holds per workspace; secrets are refused (`looks_secret`); retire never deletes.
**Privacy:** members only (`workspaces::access`, 404 otherwise; a member of another workspace gets 404; the API token, an owner of every team workspace, gets 404 on a Personal workspace's memory, F12); leaving ends access at once and the memory stays with the workspace; deleting the workspace deletes its memory (also when the last member leaves, and when an account's deletion takes a workspace with it); a person's own facts and their Personal workspace's memory stay theirs alone, admins included.
Tests: `crates/master/tests/it/memory_places_http.rs` (`a_workspace_fact_reaches_every_member_and_no_one_else`, `a_sensitive_personal_remember_in_a_team_writes_nothing_shared`, `a_members_save_waits_for_an_admin_then_reaches_everyone`, `the_switch_lets_members_saves_apply_at_once`, `replace_and_forget_of_a_workspace_fact_by_who_may_and_who_may_not`, `leaving_ends_access_and_the_memory_stays_with_the_workspace`, and the project waiting test).
**Residual:** whoever may write the shared memory (an admin, or every member with the switch on, or their agents in their own turns) can plant instructions every colleague's agent reads each turn; the quoting and the header make it data in form, not in effect: a model may still follow it.
Bounds: who may write, the confirm step for members, the 3,000-character cap, retire-not-delete with the change shown in the writer's chat, and every member can see the whole memory on the tab. `about` is the model's choice: a private detail it does not mark `sensitive` and calls "workspace" lands in the shared memory where the chat's owner may write it (an admin's own chat, shown there with Undo and on the tab with its author).
Bidi controls are shown as U+FFFD in what the model and the tab read (F11).
The members switch lives in `kv` and is not removed when a workspace is deleted (a flag keyed by an id nobody can reach again).
