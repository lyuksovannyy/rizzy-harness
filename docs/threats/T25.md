# T25

## Threat

A response leaks internals or outlives its session: a 500 with SQL text or a path, an API answer or stored file left in the browser's disk cache after logout or delete, a downgrade to plain HTTP (audit L4, L6)

## Mitigation

The outermost layer (`master/src/response.rs`) gives every response a random 64-bit request id (`x-request-id`, generated per request, never taken from the client); any 500 body is logged with that id and replaced by `{"error":"internal error","request_id":…}`, for every handler by construction, not per call site.
Every `/api/*` response, errors, stored files and 304s included, gets `Cache-Control: no-store` (the hashed UI files keep their caching).
With `--tls`, `Strict-Transport-Security: max-age=15552000` (180 days, no `includeSubDomains`: the harness does not own its host's siblings), not for `localhost` names (HSTS is per name, not per port, and would switch every other local dev server to https) or IP addresses.
Tests: `master/tests/it/hardening_http.rs`.
The logged copy of a 500 body is scrubbed of the master's known secrets (T3).
A failed write of `config.toml` is a 500 (`SaveError::Io`), not a 400 with the server's path: the four admin routes that save the config (token savings, storage, workspace policy, the provider routes) answer the fixed sentence and log the cause once, while every refusal keeps its sentence and its 400 (`master/tests/logs/save_errors_http.rs` `a_failed_config_write_is_a_500_without_the_path`, `validation_sentences_of_the_save_routes_are_unchanged`).
Residual: a refusal while building the providers (`providers::build`, for example a `secrets.toml` that is open to others or a named secret that is missing) is still a 400 whose text names the data directory; it needs an admin and a hand-edited file.
**Residual:** 5xx other than 500 (502 from a provider, 503 node offline) keep their messages; a panic in a handler closes the connection without a response; behind a TLS-terminating proxy the proxy must send HSTS.
