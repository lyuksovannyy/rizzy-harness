# T25

## Threat

A response leaks internals or outlives its session: a 500 with SQL text or a path, an API answer or stored file left in the browser's disk cache after logout or delete, a downgrade to plain HTTP (audit L4, L6)

## Mitigation

The outermost layer (`master/src/response.rs`) gives every response a random 64-bit request id (`x-request-id`, generated per request, never taken from the client); any 500 body is logged with that id and replaced by `{"error":"internal error","request_id":…}`, for every handler by construction, not per call site.
Every `/api/*` response, errors, stored files and 304s included, gets `Cache-Control: no-store` (the hashed UI files keep their caching).
With `--tls`, `Strict-Transport-Security: max-age=15552000` (180 days, no `includeSubDomains`: the harness does not own its host's siblings), not for `localhost` names (HSTS is per name, not per port, and would switch every other local dev server to https) or IP addresses.
Tests: `master/tests/it/hardening_http.rs`.
The logged copy of a 500 body is scrubbed of the master's known secrets (T3).
A failed write of `config.toml` is a 500 (`SaveError::Io`), not a 400 with the server's path: the four admin routes that save the config (token savings, storage, workspace policy, the provider routes) answer the fixed sentence and log the cause once, while every refusal keeps its sentence and its 400 (`master/tests/logs/save_errors_http.rs` `a_failed_config_write_is_a_500_without_the_path`, `validation_sentences_of_the_save_routes_are_unchanged`).
The model-listing routes (`/api/admin/providers/{id}/models`, `.../refresh`) send the server's own file trouble as a 500 as well (`ListingError::Server`); a provider that does not answer or a key that is not set keeps its 502 sentence (`a_listing_that_cannot_be_recorded_is_a_500_without_the_path`).
A `secrets.toml` that cannot be read while building the providers (a parse error, a mode open to others) is a 500 (`a_broken_secrets_file_shows_no_key_and_no_line`, `a_secrets_file_open_to_others_found_in_apply_is_a_500`).
The one refusal here that used to carry a path, a named secret that is missing, names the secret and the file name only: `secret "x" not found in secrets.toml` (`a_missing_named_secret_is_named_without_the_path`; one 4xx sentence changed on purpose).
A client of these routes therefore sees no server path from a 500, from the listing routes or from a refusal.
A change to `config.toml` and `secrets.toml` runs to its end in a task of its own even when the request is cut (`ProviderRuntime::section`, `save_cancel_http.rs`).
**Residual:** 5xx other than 500 (502 from a provider, 503 node offline) keep their messages, a 502 whose text is a provider's own message included; a panic in a handler closes the connection without a response; behind a TLS-terminating proxy the proxy must send HSTS.
**Residual:** a server stop in the middle of a provider save can still leave the new key in `secrets.toml` with the old URL in `config.toml` and the running configuration: the runtime drops spawned tasks at their next await, and nothing waits for a running section at shutdown. Each file stays whole (temp file and rename) and the window is milliseconds. The admin saves the provider again (same URL, key typed again) and both agree.
