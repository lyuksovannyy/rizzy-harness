## 2. Architecture as it bears on this cluster

- **Language and shape.** TypeScript on Node (ESM), one process per `dsh` launch, composed of Cordis plugins from YAML bundle patches. A small static C launcher (`landlock-run`) is the only native confinement code. The `web` profile is the `base` bundle (agent loop, tools, sandbox, approval, storage) plus the `web-app` bundle (HTTP server, connection fence, gateway), so the loop, the tools and the HTTP server share one process: the base patch mounts `dsh-agent-loop` and `dsh-tool-executor-native` ([base patch L514-L533](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/bundle/base/cordis.patch.yml#L514-L533), loop and executor rows) and the web-app patch adds the web server row in the same composition ([web-app patch L183-L189](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/bundle/web-app/cordis.patch.yml#L183-L189), `dsh-host-webserver`, default `127.0.0.1:3080`).
- **Loop.** `Agent.turn()` appends `turn/start`, then loops `preStep` (claims inbox messages, resolves the tool set, runs the `agent/pre-step` waterfall) and `step` (stream one model response, then run its tool calls) until the turn ends ([agent.ts L327-L433](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/agent-loop/src/agent.ts#L327-L433)).
- **Tool dispatch.** `executeToolBatch` parses arguments and groups parallel-safe calls ([batch.ts L50-L96](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/batch.ts#L50-L96)); `ToolExecutionPipeline.prepare` runs `tools/pre-execute`, resolves an `ask` through the approval service, then guards; `dispatch` runs the `tools/execute` waterfall around the body; `complete` runs `tools/post-execute` and emits `tools/result` ([pipeline.ts L190-L233](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/pipeline.ts#L190-L233)).

The single most important architectural fact for this cluster: **in the shipped composition nothing asks for approval of ordinary tool calls.** The only `tools/pre-execute` listeners that return `ask` are the experimental Auto review and the experimental Claude Code hook bridge; approval otherwise exists only for sandbox escalation and `plugin_manager`. ## 3. Findings

### The agent loop and tool dispatch

#### 1. The pipeline: pre-execute waterfall, approval, monotonic guards, body, post-execute
- What the code does: `prepare` snapshots and deep-freezes the arguments, runs the `tools/pre-execute` waterfall whose default is `allow`, turns an `ask` into an approval request, and only on `allow` runs the guards; a guard can only deny. Cancellation is checked before and after the decision. `dispatch` fuses the caller and wrapper abort signals and never abandons a started body. A throwing listener anywhere in `prepare` becomes an error result, so policy code fails the call closed.
- Trace: argument snapshot and freeze [pipeline.ts L152-L176](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/pipeline.ts#L152-L176); waterfall, ask, guards [pipeline.ts L197-L232](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/pipeline.ts#L197-L232); guards are deny-only and run after policy [tools/index.ts L379-L401](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/index.ts#L379-L401); body dispatch [pipeline.ts L258-L286](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/pipeline.ts#L258-L286).
- Edge cases and failure handling: no approval service composed, or no agent, degrades `ask` to deny ([pipeline.ts L432-L473](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/core/tools/src/pipeline.ts#L432-L473)). Parallel groups are bounded by `maxParallelToolCalls` (default 10). The turn loop has no step or turn limit: it continues while the inbox has pending messages and the model keeps calling tools.

#### 5. The approval service: fail closed, audit pair, turn-enclosed
- What the code does: `request()` refuses outside an open turn, appends `approval/asked {id, toolName, callId?, reason?}`, decides, appends `approval/decided {id, outcome}`. Outcomes are `allowed-once | rejected | cancelled | unavailable`; only `allowed-once` grants. A missing answerer, a throwing answerer or a non-vocabulary return all become `unavailable`; an abort settles `cancelled` and discards a late answer. If either append throws, `request()` rejects, so no decision escapes without its audit pair.
- Trace: [user-approval L224-L261](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/interaction/user-approval/src/index.ts#L224-L261); decision with containment and abort race [user-approval L293-L333](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/interaction/user-approval/src/index.ts#L293-L333); event schemas [types.ts L28-L60](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/interaction/user-approval/src/types.ts#L28-L60).

#### 9. No command parsing, no rule grammar, no "allow always"

## Web server authentication (accounts and server auth as they bear on safety)

#### 23. Launch token, signed cookie, Host and Origin fence
- What the code does: each process mints a 32-byte random launch token kept in memory and printed as `?token=` on the start URL. `GET /?token=` with exactly one matching token (constant-time compare) mints a cookie and redirects 303 to `./`. The cookie is `v1.<base64url JSON {authority, issuedAt, expiresAt}>.<HMAC-SHA256>`, named `dsh-auth-<sha256(authority)>`, `HttpOnly; SameSite=Strict; Path=/`, `Secure` only when this listener itself serves TLS, lifetime `cookieMaxAgeDays` (default 30). The HMAC secret is generated once and stored in the credential store, so cookies survive restarts while the launch token does not. A separate `/connect?token=` mints a `v2` cookie bound to a new API "operator" peer.
- Trace: token and cookie mechanics [browser-auth L61-L180](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/connection/src/browser-auth.ts#L61-L180); persistent secret [browser-auth L182-L199](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/connection/src/browser-auth.ts#L182-L199); index exchange [browser-auth L263-L305](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/connection/src/browser-auth.ts#L263-L305); connect [browser-auth L314-L348](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/connection/src/browser-auth.ts#L314-L348); verification checks authority, signature and lifetime [browser-auth L371-L383](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/connection/src/browser-auth.ts#L371-L383); default 30 days [connection index.ts L107-L139](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/packages/client/connection/src/index.ts#L107-L139).
