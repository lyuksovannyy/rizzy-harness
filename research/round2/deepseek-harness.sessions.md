## 3. Findings

### 3.1 Session log: events, format, folding

#### The log is an append-only, typed, contiguous event list; the model request is derived from it
- What the code does: every durable fact is a `SessionEvent` `{type, seq, time, data}` with an optional `ignorable` flag and, for the five message-producing types only, a `surfaceOp` and `sourceEventSeqs`. `Session.append` snapshots the payload to lossless JSON (rejects BigInt, Map, cycles, -0, non-finite), freezes it, assigns `seq = log.length`, validates it, then commits synchronously and notifies observers with per-listener containment. The loop builds each model request from `session.deriveMessages()` (a cached fold over surface nodes) plus the logged `request/header`, so "anything the model sees must be in the log" is true by construction for conversation content.

#### On-disk format and location: per-session JSONL, default checksummed zstd frames, header as first record
- What the code does: the backend root defaults to `$DSH_HOME/sessions` (`DSH_HOME`, else `~/.dsh`). Layout `<root>/--<normalized-cwd>--/<encoded-id>/session.vN.jsonl.zstd` (version-0 keeps the suffix-only name; raw `.jsonl` when `compression: 'none'`). The first record (first zstd frame) is a header line `{type:'session', version, id, createdAt, cwd?, parentSession?, isSeeded, origin?, delegationDepth, agentPreset?}`; then one JSON row per event; each durable append batch is one independently decodable zstd frame with the checksum flag set. Ids are escaped injectively (`~XXXX`) so `../`, NUL and separators cannot traverse; the project key is lossy by design.

#### Durability: write-behind buffer, but fail-closed flush before every model request and tool body
- What the code does: the persistence service listens to every `session/event` and buffers a structured clone per session; a timer drains the buffer after at most 200 ms in one batch (one frame, one `fsync`). On top, the checkpoint policy awaits `sessions.flush(session)` before the model stream is constructed, before every top-level tool body, and at each `agent/pre-step`; a failed flush rejects, so the adapter or the tool body is never invoked. Within a turn, then, an effect is never performed before the event that records its request is durable.

#### One writer per session: kernel `flock` lease with no expiry
- What the code does: opening a session for write takes a non-blocking `flock(2)` on `session.lock` beside the log (Windows: a named kernel semaphore); contention becomes `SessionAlreadyOwnedError`, surfaced to the UI as `session/writer-held`. There is deliberately no lease expiry: a wedged holder keeps the lock until its process exits, so a stalled writer cannot be expropriated and tear the log.
