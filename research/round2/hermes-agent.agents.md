## 2. Architecture as it bears on this cluster

- **One agent class, many forks.** Every "side" job (background review, curator, delegated child, `/btw`, compression summary) is either a second `AIAgent` built with a restricted toolset and a write-origin tag, or a plain `call_llm(task=...)` against an auxiliary slot. There is no separate "sub-agent runtime".
- **Prompt in three tiers** (`stable`, `context`, `volatile`), built once per session and cached on the agent object; rebuilt only after compaction ([system_prompt.py#L751-L826](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/agent/system_prompt.py#L751-L826): tier assembly and cache).
- **State lives in `~/.hermes/` (profile home):** `memories/MEMORY.md` and `USER.md`; `skills/` with `.usage.json`, `.curator_state`, `.curator_ledger.jsonl`, `.archive/`, `.locks/`; `.curator_backups/` (blobs and tarballs); `pending/{memory,skills}/` (staged writes); `auth.json` (credential pools); `state.db` (SQLite sessions with FTS5).
- **Write origin is a context variable** (`foreground` or `background_review`, plus an "attended" flag); almost every guard in this cluster keys on it ([skill_provenance.py#L8-L44](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/tools/skill_provenance.py#L8-L44): the origin and attendedness variables).
- **Config** is `config.yaml` with one defaults file, `hermes_cli/config_defaults.py`; every number below is a default there unless said otherwise.

### 3.2 Edit tools and formats

#### `patch` replace mode: a nine-strategy fuzzy chain, similarity tiers kept out of `replace_all`
- What the code does: `fuzzy_find_and_replace` tries, in order, `exact`, `line_trimmed`, `whitespace_normalized`, `indentation_flexible`, `escape_normalized`, `trimmed_boundary`, `unicode_normalized`, then two similarity strategies: `block_anchor` (first and last lines must match after strip; middle similarity at least 0.50 when only one candidate, 0.70 otherwise) and `context_aware` (every non-blank line at least 0.80 similar). The first strategy with a match wins. More than one match without `replace_all` is an error listing locations. `replace_all` is refused if the matches came from a similarity strategy. Replacement text is re-indented to the matched region and typographic Unicode in the file is preserved.
- Trace: strategies [fuzzy_match.py#L230-L304](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/tools/fuzzy_match.py#L230-L304); orchestration and tiers [fuzzy_match.py#L362-L413](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/tools/fuzzy_match.py#L362-L413); chain runner, ambiguity and `replace_all` rules [fuzzy_match.py#L416-L453](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/tools/fuzzy_match.py#L416-L453).
- Edge cases and failure handling: empty or whitespace-only `old_string`, and `old_string == new_string`, get tailored error text ([fuzzy_match.py#L371-L395](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/tools/fuzzy_match.py#L371-L395)). If the model pasted `read_file` output with its `N|` line-number gutter, the gutter is stripped before any similarity strategy runs, and only if no precise strategy matched the raw text ([fuzzy_match.py#L397-L410](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/tools/fuzzy_match.py#L397-L410)). ### 3.3 Compaction

#### Trigger: a fraction of the usable input window, with floors and a ceiling from the summary model
- What the code does: `threshold_tokens = (context_length - max_tokens) * threshold_percent`, with `threshold` default 0.50; windows under 512K are floored at 0.75 (raise-only). The result is floored at a minimum context length but capped at 85% of the usable window when the floor would otherwise swallow the headroom. An absolute `threshold_tokens` cap and per-model `model_thresholds` (longest substring key wins, optionally `provider:substr`) can lower it. `should_compress` is `prompt_tokens >= threshold_tokens` unless a cooldown or the "ineffective" breaker blocks it.
- Trace: defaults [config_defaults.py#L563-L595](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/hermes_cli/config_defaults.py#L563-L595); floor [context_compressor.py#L2751-L2755](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/agent/context_compressor.py#L2751-L2755); math [context_compressor.py#L2764-L2797](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/agent/context_compressor.py#L2764-L2797); per-model key resolution [context_compressor.py#L2026-L2050](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/agent/context_compressor.py#L2026-L2050); gate [context_compressor.py#L2990-L3003](https://github.com/NousResearch/hermes-agent/blob/95fc3e668fc1e13ad05d22a4f02fccc6a6d6ce02/agent/context_compressor.py#L2990-L3003).

#### Pipeline: prune, pick head and tail, one summary call, then a deterministic fallback
- What the code does: `compress()` (1) projects old tool-result bodies down to short summaries without an LLM call (tool-call arguments are never rewritten; duplicate results are de-duplicated; a just-loaded `skill_view` body is kept full); (2) chooses a protected head (the system prompt plus `protect_first_n` = 3 rows, which decays to 0 once the session has been compacted once) and a token-budgeted tail; (3) in `lean` mode (default) the tail is 2.5% of the window clamped to 10K..25K tokens and never more than 20% of the window, and the summary carries continuity: a session log, a regex-extracted anchor index (PR numbers, SHAs, paths, error strings), every real user message verbatim (24K chars newest first, 4K per message) and a `session_search` pointer; (4) makes exactly one auxiliary summary call; (5) if that fails, inserts a deterministic summary built from user asks, actions, files and errors; (6) assembles head, summary, tail and repairs orphaned tool pairs.

### 3.5 Agent-written skills and the background review

#### What triggers a self-improvement pass, and what it is allowed to do
- What the code does: two counters trigger a forked review after a turn. Memory: every `memory.nudge_interval` user turns (default 10; 0 disables; hydrated from history on resume). Skills: after `skills.creation_nudge_interval` tool-calling iterations without a `skill_manage` call (code default 10; the example config says 15). #### The ledger: content-addressed, per-entry rollback, fail-closed
- What the code does: every skill mutation by any actor (`curator`, `agent`, `user`) appends one JSON line to `skills/.curator_ledger.jsonl` with `before` and `after` file manifests `{path, sha256}`; file contents are stored once under `.curator_backups/blobs/<sha256>`. Unchanged files are dropped from an entry (a 4,000-file skill had cost 1.5 MB per patch). Size is trimmed (default 5 MB). `rollback_entry` first checks that every needed blob exists, then writes a `pre-rollback` entry capturing the current state of every touched path, then restores the `before` files and deletes files the mutation created; if the safety capture fails it aborts with nothing changed. Entry paths must be under the profile home (a hand-edited ledger must not become a write-anywhere primitive). Delete, archive and purge entries restore the whole package, filling files from the newest snapshot tarball.

#### Whole-tree snapshots and rollback (consolidation runs only)

#### Per-task fallback is a ladder: parameter repairs, credential rotation, then per-task chain, then main chain
- What the code does: when an aux call fails the recovery generator runs rungs in order: strip unsupported parameters, refresh or heal a credential or rotate the pool, then provider fallback. The fallback step tries the task's `fallback_chain` entries in order (skipping providers marked unhealthy and entries whose context window is below the task's minimum), then, for `auto` routes, the main agent's `fallback_providers` and a payment fallback; for an explicitly pinned provider only the main-agent model net, except that an auth error from a pinned provider may use only the task's own chain (it never implies an unconfigured provider hop). ### 3.10 Provider fallback, retry and credential pools

#### Retry: three attempts, jittered backoff, `Retry-After` honoured, 429s get adaptive waits

#### Credential pools: four strategies, exhaustion TTLs, key-level marking, persisted in `auth.json`

### 3.11 Stuck-loop detection, output limits and plan mode
