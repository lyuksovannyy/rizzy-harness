## 2. Architecture as it bears on this cluster

goose (Rust workspace) has been refactored since Round 1's docs: the agent loop is no longer a monolithic `reply` function. It is an ordered list of stateless "operations" over a persisted conversation. Everything below hangs off that.

- **Crates involved.** `goose-agent` (the generic state machine, sub-agent operation, approval and hook operations), `goose` (`agents/state_machine/*` holds goose's concrete operations; `agents/platform_extensions/*` holds built-in extensions), `goose-context-management` (compaction library), `goose-provider-types` and `goose-providers` (provider trait, retry), `goose-mcp` (Memory and other stdio-style built-ins).
- **The loop.** `StateMachine::step` walks the step list in order and applies the first step that returns `Applied`; `run` reloads the session from storage and repeats until a step yields or cancellation. Loop state lives in the persisted conversation, not in memory.
  - https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-agent/src/machine.rs#L154-L212 (one pass, first applicable step wins)
  - https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-agent/src/machine.rs#L233-L248 (reload, step, apply effects, loop while `Continuing`)
  - https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-agent/README.md#L1-L8 (the stated design: behaviour is a function of the persisted conversation)
- **The step order** (this is where "who decides next" lives): slash commands, tool approval, pre-tool hook, skills, recipe, tool execution, remaining tool calls, unhandled tool calls, sub-agents, steering, bang-shell, then (unless the provider manages its own context) context relevance and **compaction**, then tool-pair compaction, doctor, project, recipe retry/goal/grind, empty response, stop hook, exit on error, max turns, extras, and finally **inference** as the last step.
  - https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/agents/state_machine_builder.rs#L127-L225
- **Operation contributions to the request.** Each operation can add tools (`inference_tools`), system prompt parts (`prompt_parts`) and per-turn context parts (`moim_parts`); the machine collects them from every operation before each inference and rejects duplicate tool names.
  - https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-agent/src/machine.rs#L117-L152
- **Key types.** `Session` (conversation, `goose_mode`, `recipe`, `system_prompt_override`, `system_prompt_extras`, `parent_session_id`, `session_type`), `GooseMode` (`Auto` default, `Approve`, `SmartApprove`, `Chat`), `ExtensionLease` (a per-turn snapshot of extensions and tools).
  - https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-provider-types/src/goose_mode.rs#L22-L32
- **Process model.** The loop and its tools run in the process that hosts the session (`goose serve`/`goose acp`/CLI); sub-agents are extra sessions in the same process (section 5). No separate worker process for sub-agents.

## 3. Findings

### 3.1 System prompt assembly and tool descriptions

#### One template plus keyed "extras", rebuilt on every request
- What the code does: the base prompt is the minijinja template `system.md` (39 lines: identity, optional "turn context" explanation, "Response Guidelines: Use Markdown"). Everything else is appended as keyed `extras` under a `# Additional Instructions:` header, joined by blank lines. The prompt is rebuilt from scratch before each inference call, so edits to hint files and extension instructions apply mid-session.
- Trace:

  - `join` produces `base + "\n\n# Additional Instructions:\n\n" + extras`: https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/agents/prompt_manager.rs#L182-L196

Stable ordering (extensions sorted by name, tools sorted by name) is explicitly for multi-session prompt caching.
- Round 1: `confirmed` for "system prompt can be overridden by same-named files" (see next entry); `new (not documented)` for the keyed-extras mechanism, the Unicode-tag sanitising and the no-per-model-branching fact.
- For rizzy-harness: copy the "base template plus ordered, named contributions from each pipeline step" shape; named parts make token attribution (and a context report) trivial. Copy the Unicode-tag stripping on every injected text (hint files, extension instructions are attacker-reachable).

#### `.goosehints` and `AGENTS.md`: both are loaded, concatenated, never "either/or"; not gated on the Developer extension
- What the code does: the context filenames default to `[".goosehints", "AGENTS.md"]` (override: `CONTEXT_FILE_NAMES`). Global files come first: `<config_dir>/.goosehints`, `<config_dir>/AGENTS.md`, then `~/.agents/AGENTS.md` (only if `AGENTS.md` is in the filename list). Then local files for every directory from the git root down to the working directory (root first, cwd last), in filename order per directory. Output is `### Global Hints ... ### Project Hints ...`, inserted as the `hints` extra. `@path` tokens inside a hint file are expanded inline between `--- Content from X ---` markers, within an import boundary (git root or cwd), at most depth 3, 64 reference operations and 1 MiB expanded; a file over 128 KiB gets no reference parsing at all. The main file itself is read whole, with no size cap.

#### Subdirectory hints are discovered lazily from tool arguments, and re-derived from the whole conversation
- What the code does: each time a prompt is built, the tool-execution operation replays every agent-visible tool request in the conversation, collects `path` arguments and path-like tokens from `command` arguments (`shell_words::split`), and for each directory strictly inside the working directory (not equal to it) loads that directory's hint files plus those of its ancestors below the working directory. Each loaded directory becomes an extra named `subdir_hints:<dir>`. Because it is recomputed from history, the hints persist for the session (and vanish if the triggering messages are hidden by compaction).
- Trace: https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/hints/load_hints.rs#L26-L103 ; https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/hints/load_hints.rs#L115-L168 ; replay in https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/agents/state_machine/ops_toolcalling.rs#L931-L950
- Edge cases and failure handling: canonicalisation guards against `..` escapes (`starts_with(working_dir)`). Reading through `cat` in `shell` triggers it only if the token contains a path separator or a dot. After compaction the original tool requests are agent-invisible, so subdirectory hints drop out of the prompt until the model touches those paths again (inferred from `is_agent_visible` filtering plus `compact_messages` hiding all prior messages).
- Round 1: `confirmed` ("subdirectory files when files there are touched") with the mechanism added.
- For rizzy-harness: stateless re-derivation from the log fits an event-log design; note the lose-on-compaction consequence and pin loaded instruction files outside the compactable region.
- Confidence: read the definition (compaction interaction inferred).

#### Turn context ("MOIM") is a per-turn, agent-only user message, not system prompt; "Top of Mind" is the extension that feeds it

It is persisted so later requests within the turn reuse identical bytes, and skipped when the context limit is under 32,000 tokens. The `tom` platform extension ("Top Of Mind", no tools) contributes `GOOSE_MOIM_MESSAGE_TEXT` and the contents of `GOOSE_MOIM_MESSAGE_FILE` (each capped at 65,536 bytes).

### 3.2 Edit tools and the Developer extension

#### Developer extension: five tools, no read tool, no search tool
- What the code does: the extension exposes exactly `write`, `edit`, `shell`, `tree`, `read_image`. There is no file-read tool and no grep/glob tool; the extension instructions tell the model to use `tree`, then `rg`, `cat` or `sed` through `shell`, "always reading before editing". Windows gets a PowerShell/`findstr` variant of the instruction text. `write` is annotated destructive, `edit` destructive, `tree` read-only and idempotent, `read_image` open-world (it fetches http(s) URLs).
- Trace: https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/agents/platform_extensions/developer/mod.rs#L108-L185 ; instructions https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/agents/platform_extensions/developer/mod.rs#L42-L74 ; the test that pins the list https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/agents/platform_extensions/developer/mod.rs#L271-L279 ; default-enabled registration https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose/src/agents/platform_extensions/mod.rs#L174-L180

#### `edit` is exact, unique, single-occurrence string replacement; no fuzzy matching, no staleness check, no undo, no post-edit diagnostics
- What the code does: `edit(path, before, after)` reads the whole file, counts `before` matches with `str::match_indices`, replaces when there is exactly one, writes with `fs::write`. Zero matches: error with a "Did you mean" hint (first line of `before`, trimmed, matched as a substring of any line, 5-line context) and a numbered 20-line file preview. ### 3.7 Retry, fallback, stuck loops and mode enforcement

#### Provider calls retry transient errors three times with exponential backoff and jitter; Retry-After is honoured; nothing falls back to another provider
- What the code does: `with_retry` wraps the HTTP request in most providers. Defaults: 3 retries, 1 s initial, x2, capped at 30 s, jitter factor 0.8 to 1.2. Retried: rate limits, server errors, network errors, and (unless `transient_only`) generic request failures. Not retried: context-length errors, auth errors, refusals, and a list of "permanent" 4xx markers (Anthropic immutable-thinking-block rejections, mandatory-reasoning errors). A rate-limit error with a provider-supplied delay sleeps for exactly that delay. Retry covers establishing the stream, not a failure in the middle of a stream (mid-stream errors go straight to `error_outcome`). Databricks and Bedrock make the retry count configurable (`DATABRICKS_MAX_RETRIES`, ...); Ollama uses 10. Anthropic and OpenAI additionally retry once without replayed thinking/reasoning when the API rejects replayed blocks.
- Trace: https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-provider-types/src/retry.rs#L14-L17 ; https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-provider-types/src/retry.rs#L71-L87 ; https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-provider-types/src/retry.rs#L90-L158 ; Anthropic usage https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-providers/src/anthropic.rs#L184-L201 and thinking-strip retry https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-providers/src/anthropic.rs#L220-L240 ; mid-stream errors https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-agent/src/inference.rs#L543-L547 ; Ollama https://github.com/aaif-goose/goose/blob/14bf51817b79f6e98ca73c6eda61c11d9d5cc892/crates/goose-providers/src/ollama.rs#L47-L47
- Edge cases and failure handling: once retries are exhausted, the error becomes a visible assistant error message ("Ran into this error ... Please retry if you think this is a transient or recoverable error") and the turn ends; the user must resend. There is no switch to a second model or provider.
